## 1. 本轮三个决策问题

### Q1｜FR5 的真实运动环是否适合外环柔顺控制？
- **失败模式**：命令函数返回成功不等于机器人已开始运动；伺服模式未启动、ROS2 插件/固件版本错配、状态反馈过期或运动队列缓冲，都可能让控制器基于错误时间闭环。
- **接口**：输入 SDK/ROS2 版本、命令时间/返回码、机器人实时状态与实际 TCP/关节反馈；输出命令到运动延迟、反馈年龄、更新率、抖动、增益/相位与异常退出。
- **假设 H1-G0**：版本匹配且显式调用 ServoMoveStart/ServoMoveEnd 后，时延分布应优于未正确初始化路径；但修正后仍可能有 0.1 s 量级延迟。
- **最小对照**：静态审查当前插件；在安全无接触环境只运行已确认启停流程的低幅测试，对比直接 SDK 伺服流与版本匹配 ROS2 路径。不要为复现问题而在真实机器人上故意发送未初始化伺服流。
- **决策**：若时延/抖动或反馈年龄超出事先制定的预算，暂停导纳/接触实验，先修接口或改用经验证路径。

### Q2｜KWR75D 低载荷六维 wrench 是否足够可靠？
- **失败模式**：把 1000 Hz 采样当作低载荷测量足够精细；满量程误差、重复性、偏置、温漂和六轴串扰可能使小力/小力矩变化不可分辨。
- **接口**：输入传感器型号/协议、原始包、主机单调时钟、独立参考载荷与已知力臂；输出六轴比例/偏置、低载荷噪声、重复性、滞回、串扰、漂移与丢包指标。
- **假设 H2-G0**：KWR75D 的满量程规格折算后可能不足以稳定区分小幅接触力误差或 CoP 变化；这只是待实物校准否证的风险假设。
- **最小对照**：用独立参考载荷和已知力臂逐轴加载/卸载并重复测量；离线比较 KWR75E/F 的规格，但不在任务力范围和风险评估明确前直接换型。
- **决策**：若低载荷噪声/漂移与任务所需最小变化同量级，先重新评估量程、安装力臂或传感方案，不靠更复杂滤波制造不可观测信息。

### Q3｜机器人状态、KWR75D 与安全停止是否有可追溯的共同时间基准？
- **失败模式**：把主机接收时间当成传感器采样时间；混用机器人内置 F/T API 与外置 KWR75D；把软件状态轮询误认为独立安全链。
- **接口**：机器人状态、系统时钟（若当前版本可用）、KWR75D 串口/ROS 消息、相机时间戳、命令时间与主机 monotonic clock；输出数据年龄、跨流时差、丢帧/重复帧、同步误差及停止行为。
- **假设 H3-G0**：只有分别记录源时间（若有）、接收时间、序号/完整性和 frame_id，才能把延迟归因于机器人、驱动、滤波或控制器；软件停止 API 不能替代实体急停与独立监督。
- **最小对照**：静止采集机器人与 KWR75D 数据；在安全无接触条件下记录低幅运动命令/反馈/外部运动参考；独立验证急停、保护停、命令超时与通信断开。
- **决策**：数据新鲜度、停止行为或故障退出未测清之前，不把这些信号送入闭环接触控制，也不开展人体测试。

## 2. 四条逻辑工作流的统一综合

### A｜硬件/API
官方 SDK 文档定义 ServoMoveStart/ServoMoveEnd 为 ServoJ/ServoCart 伺服流的开始/结束；版本更新记录列出 CNDE 实时状态配置接口。官方 FAQ 的 1–16 ms 调用间隔是命令接口指导，不是实测机械臂带宽。SDK 手册把 ServoCart 的 cmdT 推荐范围写为 0.001–0.0016 s、默认 0.008 s；不同文档口径需结合现场版本向厂商确认，不能当作已验证的闭环周期。
官方 ROS2 issue #39（2026-08-26）报告 FR5、控制器固件 3.98、libfairino 2.3.8、ROS2 Humble、125 Hz 下，ServoJ 流未正确启停时命令到运动延迟 2.113 s；补齐启停后报告 0.158–0.278 s。它是开放 issue 的用户实测，不是厂商通用规格，也不是本项目结果。issue #32 在 FR20/软件 v3.9.5 报告 ServoJ 未启动导致 write 阻塞与约 20 s 控制循环超时；不同平台/版本只能作为风险证据。issue #26 仍是 velocity command interface 功能请求，不能假设插件已经提供原生 Cartesian velocity interface。
**决策**：锁定机器人软件、控制器固件、SDK、ROS2 分支/tag、操作系统与网络拓扑；检查启停生命周期、命令所有者和停止流程。当前 A/B 平台采用共同只读状态服务，运动测试期间只能有一个命令所有者。

### B｜几何与路径
本轮暂停新增曲面/轨迹算法检索，不重复 Run 8/9 与 pending Run 13 的 2D→3D、Hydra、VBRM 等工作。G0 未通过时，手眼/RGB-D/轨迹误差会被未知运动延迟和过期状态污染。后续每条轨迹数据应保留采集时间、标定版本、frame_id、曲面版本和置信度。

### C｜接触与控制
外置 KWR75D 与 FR5 内置 F/T API 是不同数据链，不可混用。wrench 从传感器原点转到接触点时必须同步处理表达坐标系和力矩参考点。单腕六维合 wrench 不能唯一恢复宽刮板整片压力分布。CoP/边缘偏载估计须等六轴符号、单位、偏置、工具载荷补偿与已知力臂验证通过后再评估。
**决策**：第一阶段只输出原始 wrench 质量指标与校准状态，不输出“已可靠识别 partial slip”或“真实法向”。力矩参考点转换要用正负方向已知的力臂工装验证符号。

### D｜baseline 与创新
不把接口修复包装成算法创新。强 baseline 按层建立：①版本匹配的 SDK 伺服流与实时状态记录；②审查并通过启停测试的官方 ROS2 硬件路径；③实测时延模型下的固定导纳；④ Mae–Kikuuwe 2024 离散 jerk-limited 导纳作为强对照。显式力/力矩控制只有在 FR5 实际 API 具备对应控制层级时才是可实现对照。Run 13 的动态 CoP/contact-frame + 置信度门控 + 有界导纳继续保留为候选假设，但 G0/G1 输入可信度更优先。

### 9｜P1：Mae & Kikuuwe 2024，位置控制机器人上的离散 jerk-limited 导纳
Ryusei Mae、Ryo Kikuuwe, “An Admittance Controller with a Jerk Limiter for Position-Controlled Robots,” Journal of Robotics and Mechatronics, 36(2):483–493, 2024-04-20, DOI 10.20965/jrm.2024.p0483。正式期刊论文，开放全文：[J-STAGE](https://www.jstage.jst.go.jp/article/jrobomech/36/2/36_483/_article)。它针对位置控制机器人与内层 deadtime，把 jerk limiter（限制位置命令三阶导数）放入 normal-cone/differential-inclusion 表述，并用 implicit Euler 推导离散算法；论文在 UR3e 上验证，报告其特定 velocity-command 模式 deadtime 为 6 ms。优点是真机实验；边界是 6 ms 只属于该平台，不能当作 FR5 参数，算法也不能修复未启动的 ServoMoveStart 或失真的传感器输入。决策：列为后续强 baseline；等 FR5 时延和 KWR75D 低载荷误差实测后再比较。

## 4. 关键工作结构化精读：Mae–Kikuuwe 2024 与接口边界

连续时间导纳可写为：

Md · x_ddot + Dd · x_dot + Kd · x = Fd − Fn

Md、Dd、Kd 是虚拟质量/阻尼/刚度，Fd 是目标法向力，Fn 是估计的实际法向力。它把力差转换成位置修正，适合没有直接末端力矩接口的机器人。

这篇论文的关键不是简单换滤波器，而是把接触约束放入 normal-cone/differential-inclusion 表述，用 implicit Euler 得到离散更新，并限制位置命令 jerk，以减少刚性接触时的高频命令突变。作者在 UR3e 上实测 6 ms deadtime，证明该设计在其平台上可运行；它没有证明 FR5 的延迟、缓冲或网络抖动相同。

本轮新证据的含义是：若伺服流未正确启动，命令到运动可能出现秒级异常；即使按 issue #39 报告补上启停，仍报告 0.158–0.278 s 延迟。离散导纳不能靠调 Md/Dd/Kd 消除未知命令队列或错误状态年龄。正确顺序是：锁定版本 → 审查启停生命周期 → 对齐命令、机器人状态与 KWR75D 时间记录 → 测延迟分布/频响 → 再比较 fixed admittance、jerk-limited discrete admittance 与 adaptive admittance。

## 6. 最小对照/台架实验

### E0｜版本、状态流与数据完整性（不接触）
保存 FR5 型号、控制器固件/机器人软件、SDK、ROS2 distro、hardware package/tag、操作系统与网络配置。静止采集机器人状态和 KWR75D 原始数据；每条记录包含主机 monotonic time、源时间戳（若有）、序号/重复帧标记、frame_id、单位与原始包。统计 P50/P95/P99 间隔、有效更新率、重复/丢失包、数据年龄、断连恢复与抖动。先验证实体急停、保护停与命令超时的实际行为。

### E1｜KWR75D 六轴低载荷标定与已知力臂
- **参考真值**：可追溯砝码/校准测力计、已知方向与长度的力臂、安装姿态记录。
- **变量**：各轴正/负方向、多个安全载荷等级、多个力臂、加载/卸载与重复装夹。
- **信号**：原始包、解析六轴值、接收时间、bias、参考载荷/力臂。
- **指标**：比例/偏置、非线性、串扰、滞回、重复性、低载荷标准差/漂移、力矩符号、CoP 误差与置信区间。
- **重复**：每个安全工况至少 10 次作为试验计划起点；若区间过宽则增加样本。
- **停止条件**：量程/过载风险、工装松动、读数饱和、数据包异常或参考设备失效。
- **决策**：若低载荷指标不满足预先分配的误差预算，先评估量程/安装/传感方案，不进入 wrench 驱动接触闭环。

### E2｜FR5 command-to-motion 与频响（无接触、单命令所有者）
- **前置**：E0 完成，实体急停可用，伺服启停流程审查通过，工作空间清空；幅度/速度由现场风险评估批准。
- **对照**：正确启停的 SDK ServoCart/ServoJ；仅在代码审查通过后比较官方 ROS2 hardware path。不要故意重放未初始化伺服流。
- **信号**：命令发送/返回时间、参考轨迹、实际 TCP/关节状态、系统时钟（若支持）、外部光学运动参考、控制循环周期、停止信号与错误码。
- **指标**：命令到运动起始延迟、P50/P95/P99、抖动、跟踪增益/相位、反馈年龄、队列长度、controller_manager overrun 与异常停止率。
- **扫频**：从低频小幅开始，逐步扩展到风险评估允许范围；0.05–2 Hz 仅是候选探索区间，不是预定安全参数。
- **停止条件**：非预期运动、状态过期、队列增长、控制循环超时、通信失联或停止路径未按协议生效。
- **决策**：只有时延与反馈新鲜度满足预先确定的控制预算，才进入固定导纳和 jerk-limited 导纳对照。

### E3｜wrench 参考点/符号单元测试
若传感器原点 S、接触点 C，r_SC 为从 S 指向 C 且在 S 中表达的向量，τ_S 是关于 S 原点的力矩，则：

- F_C = R_CS · F_S
- τ_C = R_CS · (τ_S − r_SC × F_S)

必须保证力与力矩表达坐标系一致，并用已知力臂正/负方向加载验证符号。该实验只验证坐标/参考点变换，不直接验证皮肤接触法向。

## 7. 结论分级、Gate 与下一轮

### 论文/官方材料支持
- FAIRINO SDK 文档定义 ServoMoveStart/End、ServoCart、实时状态配置与急停/安全停止状态查询；字段/周期随版本而变。
- 官方 FAQ 的命令间隔指导不等于实测机械臂带宽。
- 坤维官方规格页给出 KWR75D 量程、分辨率、重复精度、准度与 1000 Hz 采样频率；满量程折算不能替代实物低载荷校准。
- Mae & Kikuuwe 2024 在 UR3e 上验证离散 jerk-limited 导纳，论文报告其特定命令模式 deadtime 为 6 ms。

### 跨任务迁移假设
- 显式处理 FR5 伺服启停生命周期可能避免异常缓冲/阻塞；issue #39 只是风险信号，本项目仍需复测。
- KWR75D 满量程比例指标可能使低载荷变化难以可靠估计；是否不可用取决于任务力范围、实物噪声与误差预算。
- 实测延迟后，jerk-limited 离散导纳可能优于简单离散导纳；本项目尚无实测支持。

### 本硬件待测 / 不可外推
现场版本、真实命令到运动延迟、反馈更新率、跨设备时钟偏差、KWR75D 低载荷信噪比/零漂/工具载荷补偿、实体停止链，以及 FR5 是否有足够带宽的直接力/力矩控制接口均未知。UR3e 的 6 ms 不能当作 FR5 参数；KWR75D 的 1 kHz 规格不等于主机接收率；外置 KWR75D 不可与内置 F/T API 混为一谈。

### Gate 更新
- **G0：未通过/仍阻塞**。文档审计完成，但现场版本、数据年龄、端到端延迟与独立停止链尚未实测。
- **G1：未开始验收**。坐标与 wrench 参考点必须在 G0 后用刚性工装验证。
- **G2/G3/G4：暂停**。几何轨迹、CoP/contact frame 与柔顺控制依赖 G0/G1 可信输入。
- **G5/G6/G7：不推进**。FSM、安全闭环与 residual/offline RL 不得越过前置 Gate。

### 下一轮自适应优先级
1. 若取得 E0–E2 数据：分析时延/抖动/频响与 KWR75D 低载荷标定，决定控制周期和量程风险。
2. 若无硬件数据：完善只读日志器的版本/时间戳/序号 schema，并做 SDK/ROS2 启停生命周期静态审计；不转去泛搜新导纳算法。
3. G0/G1 通过后，回到 pending Run 13 的 H1，在已知曲率工装上做动态 CoP/contact-frame 真值实验。
