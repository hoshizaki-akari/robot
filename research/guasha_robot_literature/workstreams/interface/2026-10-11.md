# 专题研究线 A：FR5 / KWR75D 接口、实机可执行性与时间同步审计

日期：2026-10-11  
**专题审计，非完整 Run。** 仅写入独立 interface 路径，不修改 README/index/roundNN/project_roadmap/main。开始前读取了 README、Run 14、可用的 project roadmap 分支和 2026-10-10 interface 报告，并按未解项去重。未连接硬件、未下载或编译 SDK/驱动、未做实机测量。

## 0. 本轮仅研究三个决定性问题
1. FAIRINO 当前公开 ROS 2 v4.0.0 硬件插件的命令/反馈/伺服生命周期是否足以直接进入外环？
2. KWR75D 的满量程规格换算后，是否足以支撑低载荷力矩与接触位置估计？
3. 第三方 KWR75 ROS 2 驱动是否匹配厂商当前列出的 28/30 字节及多协议版本？其数据新鲜度、坐标、补偿和许可是否明确？

## 1. 决策摘要

| 优先级 | 发现 | 证据等级 | 工程决策 |
|---|---|---|---|
| P0 | FAIRINO 当前公开 v4.0.0 插件仅开放关节 position command/state interface；write() 调用 ServoJ，但 on_activate() 未调用 ServoMoveStart()，on_deactivate() 用 StopMotion()/CloseRPC()，未调用 ServoMoveEnd()。 | 官方仓库静态源码，未实机验证 | 不把当前插件原样接入接触闭环；先修补/核验生命周期，再测反馈与停止。 |
| P0 | 插件 read() 的失败分支没有 return ERROR，函数末尾仍返回 OK；有限值检查使用到第六个元素地址作为半开区间末端，因此漏检第六轴。 | 静态代码审查 | 修补并加单元/故障注入测试，否则状态过期可能被当作有效。 |
| P0 | 坤维官方资料目录列出 KWR75 的 28-byte RS422、28-byte RS485、30-byte RS485、Modbus RTU、TCP、UDP 等手册；第三方 ROS 2 驱动只解析 28 字节帧。 | 厂商资料目录 + 第三方源码 | 先核对实物传感器/数采铭牌与协议版本，不能按系列名默认套驱动。 |
| P0 | KWR75D 为 Fx/Fy=500 N、Fz=700 N、各力矩轴 18 N·m；准度 0.5%FS 换算为力矩约 0.09 N·m。若合力为 6 N，力矩误差折算的力臂量级约 15 mm。 | 厂商规格 + 量纲推算，不是实测 | 不承诺毫米级 CoP/边缘接触估计；先用独立参考测力设备与已知力臂验证。 |
| P1 | FAIRINO 状态结构有毫秒级机器人日历时间，另有 port 20004 反馈周期配置 API；公开文档未保证它是每帧精确采样时刻，也未证明与主机、KWR75D、相机硬同步。 | 官方字段定义；同步语义待测 | 同时保存设备时间、主机 monotonic 接收时间、样本序号和数据年龄。 |
| P1 | 第三方 KWR75 驱动在收到任意字节时刷新 last_receive_time，超时阈值 1 秒；无效/不完整字节也可能刷新 watchdog。 | 静态代码推断，未复现 | 使用“完整有效帧+序号+数据年龄”看门狗，不只看串口是否有字节。 |

**总决策：** G0 阶段先用与现场版本匹配的官方 SDK 做只读状态、命令生命周期和空载时序审计；ROS 2 service 暂作监督/调试层。v4.0.0 ros2_control 插件须经静态修补和实测后才考虑接入闭环。KWR75D 数据链须先锁定协议版本，并验证低载荷力矩误差。

## 2. Q1 — FAIRINO SDK / ROS 2 命令、反馈和停止语义

### 2.1 版本、依赖、许可和复现难度

### 2.2 静态代码审查结果
在上述 commit 的 v4.0.0 插件中：
1. 每个关节只开放 position command interface 和 position state interface；velocity/effort 代码被注释掉，effort command 未实现。
2. on_activate() 连接 RPC、读取实际关节角并同步初始命令，但没有调用 ServoMoveStart()。
3. write() 把 ROS 弧度转为度，调用 ServoJ(..., 0.008, 0, 0)。这是关节位置命令流，不是 Cartesian velocity 或 wrench command interface；cmdT=0.008 是传给 SDK 的参数，不代表实际反馈率或闭环带宽。
4. on_deactivate() 调用 StopMotion() 和 CloseRPC()，没有显式 ServoMoveEnd()。
5. read() 调用 GetActualJointPosDegree(1)，失败分支只有 ERROR 表达式而没有 return；函数仍落到 return OK，旧状态可能被当作有效。
6. 有限值检查的 std::any_of 结束迭代器指向第六元素地址；C++ 半开区间因此不检查第六轴。

以上是代码可读、未实机验证的缺陷。核心决策是：原样插件不能被视为已验证的实时控制接口。

### 2.3 官方文档究竟保证什么
- ServoMoveStart/ServoMoveEnd 用于 ServoJ/ServoCart 伺服流开始/结束。ServoCart 的 mode 0 为基坐标绝对位姿、mode 1 为基坐标增量、mode 2 为工具坐标增量；平移单位 mm、姿态单位度。手册推荐 cmdT 0.001–0.0016 s，默认 0.008 s；acc、vel、filterT、gain 标注为暂不可用。cmdT 是 API 参数，不是机械臂闭环带宽。
- StopMotion/PauseMotion 的说明要求运动指令处于 non-blocking 状态；文档没有证明它们能替代当前版本正在运行的 ServoCart 流的 ServoMoveEnd，也没有给出接触条件下停止距离/时间。应分开测 ServoMoveEnd、StopMotion、Pause/Resume、断连和硬件急停。
- 状态查询提供 GetRobotMotionDone、GetMotionQueueLength、GetRobotEmergencyStopState、GetSafetyStopState、GetSDKComState、GetRobotRealTimeState。状态结构含 year/month/day/hour/minute/second/millisecond、motion_done、mc_queue_len、安全/急停标志、TCP/关节状态与 ft_sensor_data。机器人日历时间到毫秒不等于每帧精确采样时间；ft_sensor_data 是机器人内置力传感器，不是外置 KWR75D。
- SetRobotRealtimeStateSamplePeriod(period) 配置 port 20004 状态反馈周期，单位 ms，示例值 10 ms；GetRobotRealtimeStateSamplePeriod 可读回配置。配置值不证明实际包周期、抖动、延迟或带宽。
- SetRobotStopOnComDisc 可设置端口通信断开时停止；端口索引对应 8080、8083、20002、20004，确认时间 0–5000 ms。这是软件/控制器行为，不等于安全认证硬件急停。
- 官方文档：[Python SDK 总览](https://documentation.fairino.co.in/SDKManual/python_intro.html)、[运动接口](https://documentation.fairino.co.in/SDKManual/PythonRobotMovement.html)、[状态查询](https://documentation.fairino.co.in/SDKManual/PythonRobotStatusInquiry.html)、[状态结构](https://documentation.fairino.co.in/SDKManual/PythonRobotStatusFeedback.html)、[反馈周期/断连停机](https://documentation.fairino.co.in/SDKManual/PythonRobotOthers.html)。

官方 ROS 2 issue [#39](https://github.com/FAIR-INNOVATION/frcobot_ros2/issues/39) 报告某台 FR5、固件 3.98、libfairino 2.3.8、Ubuntu 22.04、ROS 2 Humble、125 Hz 测试中，ServoJ 未正确括起时命令到运动延迟约 2.11 s；补齐 start/end 后报告约 0.16–0.28 s。这是特定配置的用户测量，不是厂商规格，也不是本项目实测。当前公开 v4.0.0 源码静态检查仍可见生命周期缺口。issue [#26](https://github.com/FAIR-INNOVATION/frcobot_ros2/issues/26) 请求 velocity command interface；当前插件仍只开放 position interface。

**实现选择：** G0 首选版本匹配的官方 SDK 做只读状态和受限空载运动审计；ROS 2 service 先作监督/调试层。修复生命周期、读取错误返回和六轴校验后，再评估 ros2_control。Cartesian ServoCart 必须独立验证坐标模式、命令节奏和停止行为。

## 3. Q2 — KWR75D 低载荷测量和协议适配

### 3.1 厂商规格与量纲换算
坤维官方 KWR75 页列出 KWR75D：Fx/Fy 500 N、Fz 700 N、Mx/My/Mz 18 N·m；分辨率 0.03%FS、重复精度 0.1%FS、准度 0.5%FS、采样频率 1000 Hz。官方注明部分参数依赖配套数采模块，准度包含串扰、滞后和非线性等误差：[官方规格](https://www.kunweitech.com/products/866.html)。

| 轴 | 满量程 | 0.03%FS | 0.1%FS | 0.5%FS |
|---|---:|---:|---:|---:|
| Fx/Fy | 500 N | 0.15 N | 0.5 N | 2.5 N |
| Fz | 700 N | 0.21 N | 0.7 N | 3.5 N |
| Mx/My/Mz | 18 N·m | 0.0054 N·m | 0.018 N·m | 0.09 N·m |

这是规格换算，不是实测精度。若 0.5%FS 适用于实际传感器+数采组合，0.09 N·m 力矩误差除以 6 N 合力，等于约 15 mm 的力臂量级；它不是实际 CoP 误差的断言，而是提示低载荷接触位置估计可能对力矩误差极敏感。采样率、分辨率、重复性、准度、零漂、温漂和串扰不可混为一谈。

### 3.2 官方协议目录与数采型号
坤维官方资料目录列出多个 KWR75 版本：
- V23.6.75.11.4LA-460800_28Bytes_422：RS422、28 字节；
- V23.6.75.11.4LB-460800_28Bytes_485：RS485、28 字节；
- V25.6.75.7.3LB-460800_30Bytes_485：RS485、30 字节；
- V24.6.75.12.1MB-115200_Modbus RTU；
- 另有 TCP/UDP 版本。
来源：[坤维官方资料下载第 3 页](https://www.kunweitech.com/services/149/p3/)。KWH06C100HL 数采模块也有 RS422/RS485/CAN 不同型号，规格列出 24-bit、1000 Hz：[官方模块页](https://www.kunweitech.com/products/454.html)。实际接口、帧长和波特率必须按实物铭牌与对应手册确认。

### 3.3 第三方驱动
仓库：[ian-chuang/kwr75_force_sensor_ros2](https://github.com/ian-chuang/kwr75_force_sensor_ros2)，humble 分支 commit a68e4d5da63ca1c6b2c0733cab24df21535c0db9（2024-04-05）。README 声明只在 Ubuntu 22.04 + ROS 2 Humble 测试；依赖 ament_cmake、hardware_interface、pluginlib、rclcpp、rclcpp_lifecycle、serial_driver 和 force_torque_sensor_broadcaster；Apache-2.0。未下载、编译或实机验证。源码：[README](https://github.com/ian-chuang/kwr75_force_sensor_ros2/blob/humble/README.md)、[驱动源码](https://github.com/ian-chuang/kwr75_force_sensor_ros2/blob/humble/src/hardware_interface.cpp)、[头文件](https://github.com/ian-chuang/kwr75_force_sensor_ros2/blob/humble/include/kwr75_force_sensor_ros2/hardware_interface.hpp)、[CMake](https://github.com/ian-chuang/kwr75_force_sensor_ros2/blob/humble/CMakeLists.txt)。

静态代码检查：
1. DATA_SIZE=28、MAX_FORCE=200 N、MAX_TORQUE=8 N·m，与 KWR75D 500/700 N、18 N·m 量程不匹配。
2. 串口参数由配置读取；无流控、无校验、1 stop bit；启动命令 0x48 AA 0D 0A。README 称其启动 1 kHz 数据流。
3. 六个 float 分别乘 9.81，注释假定原始前三轴为 kg、后三轴为 kg·m，再输出 N/N·m；必须用实际协议和已知载荷验证。
4. 解析器只接受恰好 28 字节帧；如果实物使用厂商列出的 30-byte RS485 版本，很可能不兼容。
5. receive_callback() 在验证完整帧前就更新时间；无效/不完整字节也可能刷新 last_receive_time。read() 超时为 1 秒，远慢于逐样本控制监督需求。
6. 每次回调只复制最后一个完整帧到单一缓存；若回调包含多帧，较早帧可能丢弃。
7. 没有每样本设备时间戳、样本序号、frame_id 或数据年龄接口；只有主机接收时间。
8. 驱动只做单位换算和 NaN/量程检查；未实现工具质量/CoG 的姿态相关重力补偿、惯性补偿、坐标变换、力矩参考点平移或 bias 标定。设备端是否已补偿，公开驱动不能证明，须由对应手册和静态/动态载荷测试确认。

因此该驱动仅作为协议/ROS2 接口参考；如复用，应配置化帧长/量程/单位、逐帧消费缓冲区、仅在有效帧时更新 watchdog，并分别发布 raw wrench、补偿后 wrench、样本序号、接收时间和数据年龄。

## 4. Q3 — 时间同步、wrench 参考系与最小安全实验

### 4.1 时间字段
所有节点使用主机 steady_clock 记录单调时间；ROS time 用于可视化，不用于计算可能跳变的延迟。至少记录命令发送/返回、机器人状态接收、机器人日历时间、F/T 接收、传感器源时间（若有）、RGB-D 设备/接收时间、有效帧状态、样本序号和数据年龄。若协议没有源时间戳，明确写 unknown，不能把接收时间伪装成采样时刻。可用重复 RPC 查询估计机器人时钟相对主机时钟的偏差/不确定度；相机/DAQ 支持时优先用共同 TTL/PPS 对齐。没有共同硬件触发时，应报告同步误差区间，不宣称硬同步。

### 4.2 wrench 处理
- 坐标/参考点：向厂商取得准确 KWR75D/数采手册，确认六轴正方向、单位、传感器坐标轴、力矩参考原点、源时间戳和设备端补偿策略。外置 KWR75D 不等于 FR5 内置 ft_sensor_data。
- Bias：无外力、固定姿态采静态基线；检查热机前后与姿态变化漂移，不能把接触力本身归零。
- 重力/CoG：用已知工具质量与 CoG，或多姿态静态标定估计重力 wrench，并用独立载荷验证。
- 惯性：静态重力补偿不能消除动态惯性项；先静态加载，再做低加速度、无接触运动。
- 参考点平移：从传感器原点转到刮板/接触点时，对完整 wrench 做坐标旋转和力矩平移；用已知正/负方向力臂验证符号与量纲。
- 宽刮板的腕部 resultant wrench 不能唯一恢复完整压力分布；CoP 必须用仪器化接触面/压力阵列真值验证。

### 4.3 最小安全实验（不做真人接触）
**Gate A：版本与静态状态流。** 锁定 FR5、控制器固件/软件、WebApp、SDK、ROS 2 发行版、插件 commit 和网络拓扑；保存 GetSoftwareVersion/GetSDKVersion 等返回。记录 GetRobotRealTimeState、GetSystemClock、GetRobotRealtimeStateSamplePeriod、GetMotionQueueLength、GetRobotMotionDone 和安全状态。静止采集至少 10 分钟，统计有效反馈率、样本间隔、陈旧/重复值、P50/P95/P99/最大数据年龄与错误码。任何读取错误或状态过期超出预先阈值即取消运动测试。

**Gate B：命令延迟与停止。** 先修补并审查伺服生命周期，不故意发送未初始化伺服流复现延迟。在空旷、无接触、受限工作空间，由单一命令所有者执行经批准的低速小位移/低频轨迹。记录发送/返回时间、实际 TCP/关节状态、队列长度、motion-done、错误码和独立外部位移参考。分别测试 ServoMoveEnd、StopMotion、Pause/Resume、通信断连和实体急停，记录触发至停止时间/距离。指标包括命令到首个可测运动延迟、P50/P95/P99/max、反馈周期/抖动、有效刷新率、跟踪误差、幅值衰减/相位滞后与停止距离。API 阻塞、运动异常或停止路径不确定即停止并人工复核。

**Gate C：KWR75D 协议与静态力矩校准。** 记录铭牌、数采模块、协议/固件、接口、波特率、帧长、手册版本和原始字节。机器人静止且工具不接触人体/软体，使用独立参考测力设备、已知载荷与已知力臂逐轴正/负方向加载、重复加载/卸载。统计有效帧率、帧长、丢帧/重复/无效帧率、接收间隔、样本年龄、零漂、噪声、重复性、比例/交叉轴误差、力矩误差与等效接触点误差。协议不匹配、符号/单位不明、样本连续丢失或误差超预算时不得接入闭环。

**Gate D：跨流同步与低频频响。** 空载低频运动，相机对准固定标靶，传感器由独立工装施加可重复的缓慢载荷阶跃。尽可能用同一 TTL/DAQ 事件对齐；无硬件同步时报告估计偏差与不确定度。只在预先确定的安全频率范围内做小幅正弦/扫频，测命令→位姿和参考载荷→F/T 输出的增益、相位、延迟与噪声。不预设 FR5 或传感器带宽；异常振荡、过量程、时戳不可解释或停止链不可靠时立即停止。

### 4.4 必须现场核验
- FR5 机械/控制器版本、SDK tag、ROS 2 发行版与安装插件 commit；当前插件是否已修补。
- KWR75D 准确协议手册、传感器固件、数采型号、接口/帧长/波特率、源时间戳、wrench frame/reference point 与设备端补偿策略。
- 实际工作力/力矩范围与允许误差预算。

## 5. 证据等级与交给主总控的行动项

**官方已证实：** FAIRINO 文档定义伺服生命周期、ServoCart 模式/单位/cmdT、状态/队列/安全查询、20004 反馈周期与断连停止 API；发行页列出 Python SDK v2.3.0 / robot v4.0.0；坤维官方规格和下载目录列出 KWR75D 量程、百分比规格、1000 Hz 与多协议手册。

**代码可读但未实机验证：** FAIRINO v4.0.0 插件生命周期缺口、position-only interface、读取错误未返回、有限值检查排除第六轴；KWR75 驱动固定 28 字节帧、200 N/8 N·m 阈值、9.81 换算、单帧缓存与按串口活动刷新的 1 秒 watchdog。

**本项目必须实测：** 命令到运动延迟、状态反馈率/抖动/频响、停止时间/距离；KWR75D 协议兼容性、每帧完整性、样本年龄、六轴单位/符号、低载荷噪声/漂移/交叉轴误差、力矩参考点与补偿；机器人/F/T/RGB-D 的同步不确定度。

行动项：
1. 当前 v4.0.0 ros2_control 插件标记为“待修补和 G0 实测”，先修复生命周期、读取错误返回和第六轴校验。
2. 按实物锁定 KWR75D 协议与数采型号；不以第三方 28-byte RS422 假设代替证据。
3. 将有效样本年龄设为硬约束，分别记录原始帧、有效帧、样本序号、接收时间和 frame/reference-point 元数据。
4. 先用已知载荷和力臂做静态标定/补偿验证；若误差预算不满足目标，重新评估量程/数采/外部真值，不用复杂 CoP 算法掩盖输入不确定性。
5. 本报告只建议空载、工装和仪器化体模实验，不建议真人接触测试，不给出或推定人体安全力阈值。

**最终决策：** 当前阻塞点不是缺少高级力控算法，而是公开 ROS 2 插件的伺服生命周期/反馈错误处理、KWR75D 协议版本和低载荷 wrench 误差预算尚未通过验证。先修接口、锁协议、测时间和力矩误差，再决定固定导纳或更高级控制方法能否可靠部署。
