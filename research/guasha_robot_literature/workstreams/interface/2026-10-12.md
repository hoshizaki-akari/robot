## 1. 决策摘要

### 决策 A：先锁定 KWR75D 的“传感器 + 数采模块 + 协议 + 手册修订版”，再写解析器

当前官方产品页列出 KWR75D：Fx/Fy 量程 500 N、Fz 700 N、Mx/My/Mz 18 N·m；分辨率 0.03%FS、重复精度 0.1%FS、准度 0.5%FS、标称采样频率 1000 Hz，接口可选 RS422、RS485、Modbus、CAN/CAN-FD、TCP/UDP、EtherCAT、USB 等。官方说明部分参数取决于配套数采模块，准度包含串扰、滞后和非线性等误差因素。  
来源：[坤维 KWR75 系列官方规格页](https://www.kunweitech.com/products/866.html)。

但官方域名下可检索到的旧版 RS422 手册与当前产品页并不能直接拼成一个无歧义的协议契约：
- 2023-11-29 版 RS422 手册索引中的 KWR75D 系数表列出力值系数 160/4096 kg、力矩系数 4.0/4096 kgm；同一手册描述 0x43 AA 0D 0A 停止转换/发送，0x49 AA 0D 0A 请求一次转换结果，并称首次命令启动内部刷新、之后返回以 0x49 开头且以 0x0D0A 结尾的 12-byte 数据，内部结果以 1 kHz 刷新。  
来源：[官方域名的 KWR75 系列 RS422 手册（2023-11-29）](https://www.kunweitech.com/uploads/editor/file/20231129/1701221426252418.pdf)。
- 2023-01-09 版 RS422 手册是另一份历史文档；其型号规格表也不能自动替代实物对应版本。  
来源：[官方域名的 KWR75 系列 RS422 手册（2023-01-09）](https://www.kunweitech.com/uploads/editor/file/20230109/1673224974273897.pdf)。
- **链接可达性限制：** 搜索索引可检索到上述官方域名 PDF 的标题与部分文本，但本轮直接打开返回 404/超时；因此不能声称已成功下载并逐页核验。需向坤维索取与实物序列号、数采模块和通信协议对应的当前手册。
- 第三方 ROS 2 驱动 ian-chuang/kwr75_force_sensor_ros2 的 humble 分支（commit a68e4d5da63ca1c6b2c0733cab24df21535c0db9，2024-04-05）却将帧长固定为 28 bytes，按 6 个 float 在字节偏移 2/6/10/14/18/22 解析，使用 0x48 AA 0D 0A 启动连续数据，并将前 3 轴乘 9.81 转 N、后 3 轴乘 9.81 转 N·m；硬编码 MAX_FORCE=200 N、MAX_TORQUE=8 N·m。README 声称只在 Ubuntu 22.04 + ROS 2 Humble 测试。  
来源：[驱动 README](https://github.com/ian-chuang/kwr75_force_sensor_ros2/blob/humble/README.md)、[驱动头文件](https://github.com/ian-chuang/kwr75_force_sensor_ros2/blob/humble/include/kwr75_force_sensor_ros2/hardware_interface.hpp)、[驱动实现](https://github.com/ian-chuang/kwr75_force_sensor_ros2/blob/humble/src/hardware_interface.cpp)。

**工程结论：** 这并不证明任一文档必然错误；它证明“系列名称相同”不足以确定帧格式、系数或命令时序。不能把当前产品页量程、旧手册系数和第三方 28-byte 解析器直接拼接使用。须由铭牌、数采型号/固件、购买配置、厂商确认的对应手册和原始串口字节共同锁定协议。当前第三方驱动只能当作协议实现参考，不能作为 KWR75D 已兼容的证据。

### 决策 B：KWR75D 的规格换算足以触发 CoP 风险验证，但不足以判定传感器不合格

以官方页面的百分比满量程参数作**量级筛查**（不是统计标准差，也不是对每个实物的保证误差）：

| 指标 | Fx/Fy 500 N 满量程 | Fz 700 N 满量程 | 各力矩轴 18 N·m 满量程 |
|---|---:|---:|---:|
| 0.5%FS 准度量级 | 2.5 N | 3.5 N | 0.09 N·m |
| 0.1%FS 重复精度量级 | 0.5 N | 0.7 N | 0.018 N·m |
| 0.03%FS 分辨率量级 | 0.15 N | 0.21 N | 0.0054 N·m |

这些数值来自官方规格的直接乘法换算；产品页没有给出足以替代本项目校准的低载荷误差曲线、零漂曲线或六轴协方差。准度还受数采模块配置影响。

对于局部平面、坐标轴和力矩参考点已统一的简化模型，CoP 估计常写成
\[
x_{\mathrm{CoP}}\approx -M_y/F_z,\qquad
y_{\mathrm{CoP}}\approx M_x/F_z
\]
（正负号随实际坐标约定而定）。当法向力较小，分母会放大力矩与法向力误差。一阶近似为
\[
|\delta x|\lesssim |\delta M_y|/|F_z|+
|M_y|\,|\delta F_z|/|F_z|^2.
\]
若仅用 0.09 N·m 作为力矩满量程误差量级示例、法向力取 6 N，则第一项约为 15 mm；同一规格换算的 Fz 误差量级 3.5 N 相当于 6 N 目标的 58%。**这不是说实测 CoP 一定错 15 mm，也不是说真实 6 N 读数一定有 3.5 N 误差**；它说明不能仅凭“1000 Hz”或“0.03%FS 分辨率”就宣称个位数牛顿下的 CoP 足够精确。

为硬件选择提供的下一步不是立即换传感器，而是把实际力包络纳入对比：
- 当前 KWR75D：量程较宽，规格换算下低载荷相对满量程的误差风险较大。
- 官方同系列低量程候选：KWR75E（30 N / 30 N，1.5 N·m）、KWR75A（50 N / 50 N，2 N·m）、KWR75F（100 N / 100 N，4 N·m）；其 0.5%FS 力矩量级分别约 0.0075、0.01、0.02 N·m。按 6 N 仅做第一项 CoP 误差量级示例，约 1.25、1.67、3.33 mm。仍需验证工具切向峰值、碰撞/过载、传感器机械接口与数采配置，不能仅按目标法向力选型。
- 如果实物已确定为 KWR75D，应先测真实偏置、噪声、重复性、六轴串扰和已知力臂误差；在结果通过误差预算前，只把腕部 wrench 用于经过验证的力监测/保守控制，不把它当作高精度真实接触位置真值。

### 决策 C：FR5 的命令周期、状态流和暂停返回码必须分开验证

官方 Python SDK 发布页列出的当前发行版为 v2.3.0_robot_v4.0.0，tag commit 9541beaab0662dc8c267c0b9ba925aaf14858a77（发布于 2026-09-22）；官方 SDK 仓库许可为 Apache-2.0。  
来源：[官方 SDK release/tag](https://github.com/FAIR-INNOVATION/fairino-python-sdk/releases/tag/v2.3.0_robot_v4.0.0)、[官方 SDK 仓库与许可证](https://github.com/FAIR-INNOVATION/fairino-python-sdk)。

静态检查该 tag 的 linux/fairino/Robot.py 得到：
- ServoCart(mode, desc_pos, exaxis, pos_gain, acc, vel, cmdT, filterT, gain) 是笛卡尔伺服命令；mode=0 表示基坐标绝对运动、mode=1 基坐标增量、mode=2 工具坐标增量。文档将 cmdT 定义为指令下发周期，建议 0.001–0.0016 s，但函数默认值为 0.008 s；acc、vel、filterT、gain 在该版注释中标为暂不开放。该方法注释本身没有完整说明 desc_pos 六个分量的单位与力矩参考系，必须对照与实物匹配的正式 API 文档确认，不能只根据方法名猜单位。
- ServoMoveStart() / ServoMoveEnd() 被注释为 ServoJ/ServoCart 的配套伺服生命周期接口。
- StopMotion() 返回底层调用的错误码；但 PauseMotion() 的该版实现发送 PAUSE 消息后直接 return 0，没有在该方法内等待或校验机器人状态。这意味着 PauseMotion()==0 不能单独当作机器人已经静止/暂停的证据。
- GetRobotRealTimeState() 返回 SDK 当前缓存的状态包；GetMotionQueueLength()、GetRobotMotionDone() 也从状态包取值。它们的实际刷新频率和数据年龄取决于机器人软件、SDK、状态反馈配置和通信，不由 Python 方法被调用的次数决定。

版本兼容尤其重要：官方 C# SDK 的 robot v3.9.5 发布说明明确记录了状态反馈从固定长度 20004 机制转向 20005/CNDE 可配置反馈；官方 Python SDK 发布历史将 v2.2.5 与 robot v3.9.5 绑定，而当前 v2.3.0 对应 robot v4.0.0。3.9.4 及更早版本与 3.9.5+ 的反馈配置路径不同；不能只按机器人型号判断现场实际使用哪条状态流，必须记录确切 SDK tag、控制器版本、实际端口和配置字段。  
来源：[官方 Python SDK 版本绑定发行页](https://github.com/FAIR-INNOVATION/fairino-python-sdk/releases)、[官方 C# SDK 发布说明（含 3.9.5 状态反馈变更）](https://github.com/FAIR-INNOVATION/fairino-csharp-sdk/releases)。

特别提醒：ServoCart.cmdT 的建议周期或调用频率不等于实机闭环带宽；即使指令接口允许更快调用，也不能推断状态反馈同速、命令无排队、机械臂能跟踪该频率，或外环导纳具备对应相位裕度。必须测命令发送、实际位姿反馈、队列状态与外部位移参考之间的延迟和相位。

## 3. 最小安全台架实验：先锁协议和误差，再接闭环

所有测试只在空载、刚性工装、独立测力工装或仪器化软体体模上进行；**不建议真人接触测试**。人体目标力阈值不得从其他机器人或本表规格推定。

### G0-A：KWR75D 身份与协议指纹

**信号列表**
- 传感器铭牌、序列号、型号后缀、固件版本（若可读）、数采模块型号/固件、通信接口、波特率；
- 原始 TX/RX 字节、主机 steady_clock 接收时间、帧长、解析成功/失败、样本序号（若协议有）、命令发送时间；
- 驱动解析出的六轴值、单位、量程状态、数据年龄。

**方法**
1. 不连接控制器闭环，保存启动、连续读取、停止的原始串口/网络数据。
2. 用逻辑分析仪或串口抓包确认真实帧头/帧尾、长度、字节序、数据类型、校验、是否每次命令返回一帧或连续推送。
3. 对比官方手册与第三方驱动：不得在未知协议上反复发送不同启动/停止命令；先让厂商确认与实物对应的命令序列。
4. 静置采集至少 10 min；报告有效输出率、帧间隔 P50/P95/P99/max、丢帧/重复帧/解析失败率和最长数据年龄。若设备无源时间戳，接收时间不能当成传感器采样时间。

**失败停止条件**
- 型号/手册不匹配、帧长不稳定、单位/符号未确定、数据无更新、解析失败或停止命令行为不明：结束测试，不接入任何力控环。

### G0-B：多姿态 gravity + bias 与已知力臂标定

**信号列表**
- 六轴 raw wrench、校准后 wrench、主机单调时间、传感器温度（若可读）、机器人关节/TCP 位姿及其接收时间；
- 工具质量、重心位置、安装姿态、已知载荷、加载方向、力臂、独立参考测力值；
- 每个工况的有效样本数、残差、重复加载/卸载轮次。

**方法**
1. 工具无接触，在多种安全静态姿态采样，分别拟合零点 bias 和姿态相关重力 wrench；不能用单姿态归零替代。
2. 用独立参考力计和已知力臂，逐轴正负方向加载；检查 N/N·m 单位、六轴正方向、交叉轴误差、力矩参考原点和工具 CoG。
3. 将传感器坐标下的 wrench 转到工具/刮板坐标时，分别测试旋转和参考点平移；用已知正/负力臂验证符号。
4. 分开报告分辨率、静态噪声、重复性、零漂、准度残差和动态惯性残差；不要把这些指标合并成一个“精度”。

**失败停止条件**
- 正负方向符号不对、载荷—输出不单调、卸载后零点不可重复、误差超出预先批准的力/CoP预算：不进入闭环。若只满足法向力监测但不满足 CoP 预算，保留力监测用途并禁用未经验证的接触位置反馈。

### G0-C：FR5 状态流、伺服生命周期与暂停/停止确认

**信号列表**
- GetSoftwareVersion / SDK 版本 / 控制器版本；
- 当前实际使用的 20004 或 20005/CNDE 状态流配置、状态包到达时间、机器人时间字段（若存在）、有效字段更新时间；
- ServoMoveStart/End、ServoCart/ServoJ 命令发送/返回时间、cmdT、实际 TCP/关节位姿、GetMotionQueueLength、GetRobotMotionDone、安全状态与错误码；
- PauseMotion、StopMotion、物理急停触发时间；外部独立位移/视频时间戳。

**方法**
1. 先静止采集至少 10 min，分别计算有效反馈率、每字段更新间隔、P50/P95/P99/max 数据年龄、陈旧字段比例和通信错误。
2. 只在空旷、限速、无接触、独立急停可用的环境执行小幅低频运动；单一命令所有者，不同时从 MoveIt、ROS2 与自写 SDK 发命令。
3. 分别测试伺服启动、伺服结束、暂停、停止、通信中断与实体急停；以外部位移参考测量触发到实际减速/静止的延迟和距离。PauseMotion()==0 仅作为 API 返回，不作为停止证据。
4. 在预先批准的低频范围测幅值衰减、相位滞后、命令到首个实际运动延迟、跟踪误差和停止距离；逐步提高频率时如有异常立即回退。

**失败停止条件**
- 伺服生命周期不明、状态字段过期/静默陈旧、命令返回与实际运动不一致、暂停/停止无法通过外部位移确认、任何异常运动或急停链失效：停止全部运动试验，不进入接触测试。

### G0-D：跨设备同步与实际闭环时序

- 所有主机日志统一用单调 steady_clock；ROS wall/system time 仅用于展示，不用于延迟计算。
- 机器人时间、RGB-D 硬件时间、KWR75D 设备时间若存在，必须分别保存原值，不要在驱动层静默改写成同一时钟。
- 若传感器没有每样本时间戳，先报告“采样时刻未知、只有接收时间”。优先用共同 TTL/DAQ 事件；若设备不支持共同触发，使用逻辑分析仪/独立数据采集设备测通信边沿与外部阶跃，给出时钟偏差和不确定度区间，而不是声称硬同步。
- 对齐后统计 wrench 与实际位姿的相对数据年龄、抖动、丢帧，以及命令→运动和载荷→测量的延迟/相位。1000 Hz 内部刷新、ServoCart 的 cmdT、SDK 函数调用次数都不能代替这些实测量。

## 4. 交给主总控的决策与未解项

### 已由官方资料支持
- 当前 KWR75 系列产品页列出型号间不同量程、0.5%FS 准度、0.1%FS 重复精度、0.03%FS 分辨率、1000 Hz 标称采样与多种通信接口。
- FAIRINO 官方 Python SDK 有明确的版本绑定发行版；v2.3.0_robot_v4.0.0 与 robot v4.0.0 对应。
- SDK 文档区分 ServoCart 的基/工具坐标运动模式、cmdT 指令周期与伺服开始/结束接口。

### 代码可读但未实机验证
- KWR75 第三方 ROS2 驱动的 28-byte、float、×9.81、200 N/8 N·m 假设以及 Ubuntu 22.04/ROS2 Humble 依赖声明。
- SDK v2.3.0 的 PauseMotion() 返回 0 不能证明机器人已暂停；需由状态与外部位移确认。
- SDK 状态流的 20004/20005 配置差异与字段刷新语义，须按现场 SDK/控制器配置核对。

### 本项目必须实测/向厂商确认
1. 现场 FR5 控制器固件、机器人软件、SDK tag、ROS2 插件 tag/commit、OS 与 ROS2 发行版。
2. KWR75D 序列号、数采模块、协议/固件、手册修订版、真实帧长/字节序/缩放系数/采样时间戳/参考原点/表达坐标系/设备端补偿。
3. KWR75D 在项目真实载荷区间内的零漂、低载荷准度、重复性、六轴串扰和已知力臂 CoP 误差。
4. FR5 的实际状态反馈率、每字段更新周期、命令延迟/抖动/相位、伺服启停/暂停/停止距离。
5. FR5、KWR75D、RGB-D 之间的同步不确定度。

**本轮最终建议：** 不把第三方 KWR75 ROS2 驱动直接用于 KWR75D 闭环；不把 KWR75D 的标称 1 kHz 当作实际输出率；不把 ServoCart.cmdT 当作闭环带宽；不把 PauseMotion()==0 当作已暂停。先完成 G0-A/B/C，之后才决定 KWR75D 是否足以支撑 CoP、是否需降低量程或采用独立接触真值，以及 FR5 外环能否进入导纳控制。

**本报告没有执行任何实机实验、SDK 下载/编译或控制器调参；所有这些项目均保持待现场核验。**
