## 一、这本教材怎么用

1. **先读本节"知识地图"**，知道整条技术链路长什么样、每一段由哪一轮负责。
2. **按"学习路线图"从 run2 顺读到 run12**——每一轮都承接上一轮、为下一轮铺垫，像连续剧。
3. 读到不懂的词，跳到 [`glossary.md`](glossary.md)；模块里首次出现的词也都自带一句白话+比喻。
4. 每轮末尾有「这一轮你该记住的 3 件事」，是最小复习单位。

**读者定位**：完全零基础。假设你对机器人/中医刮痧都没系统了解，所以术语一律从第一性原理解释，不假设你懂"TCP、法向、6D力矩、导纳控制"。

## 二、知识地图：整条技术链路

刮痧机器人要解决的，本质是一条流水线。下面把主链路拆成 7 段，**标注每段由哪几轮重点攻克**（编号即 run 轮次）：

```
[1] 曲面感知        Eye-in-Hand RGB-D 看背部/软体曲面
        │   run7(全链路) · run8(画线→3D) · run9(局部曲面约束)
        ▼
[2] 人工标线轨迹      人在背上画路线 → 变成机器人能走的 3D 路径
        │   run6(标线) · run8(2D↔3D映射) · run9(画线baseline)
        ▼
[3] 刮板接触坐标系     把板当作"已知几何 + 接触点/线"，而非一个点(TCP)
        │   run3(板几何+接触坐标系) · run4(等效CoP)
        ▼
[4] 在线接触/法向/位置估计   RGB-D + 6D力觉 实时猜"板贴在哪、压偏没"
        │   run3 · run4 · run5(摩擦/刚度) · run6(baseline) · run7(力矩净化) · run9
        ▼
[5] 曲面恒力/姿态柔顺控制   贴着弯软的背，稳定恒力地刮
        │   run3(导纳恒力) · run5(变阻抗) · run6(有界变阻抗) · run7(四层) · run10(运动环瓶颈) · run11(动态接触框架/控制时延)
        ▼
[6] 前刮恒力 / 轻力回程 状态机   用力刮 → 收力返回 两套力度
        │   run6(七状态双向) · run9(energy-tank安全)
        ▼
[7] 后续 RL（后置）   只在"高层力/参数"做自适应，不替代底层安全
            run7(RL做高层wrench自适应)
```

**一句话总纲**：让机器人"看得见曲面、摸得清力、刮得稳、不伤人"——前 6 段是地基，第 7 段是锦上添花。

## 四、每轮导读（读完应能回答）

- **run2（开篇）**：第一版系统**不必先上强化学习**——按摩机器人、背部三维重建、未知曲面自适应导纳、软组织恒力等相邻领域已分别验证各段可行。真正的难点不是再发明控制器，而是把"曲面几何＋接触力学＋刮板工具特性"拧成一体。四个待验证空档：宽刮板接触位置标定、6D力矩修正法向、未知曲面恒力、低频导纳实机稳定性。

- **run3（接触位置/力矩修正法向）**：把"板当成一个点"升级为"已知几何 + 在线估接触位置 + 用受力歪斜自动摆正板"。核心是 `τ=r×f` 反推接触点与偏载、`ω=T_c×z` 用接触力矩摆正板贴未知曲面并恒力（Li 2023 可直接当 baseline）；视觉被板遮挡时"前视看几何 + 力觉管接触后验"互补；低频导纳也能落地（多姿态标定、50 Hz 外环已被医疗软接触验证、加加速度限制与硬阈值）。坑：软组织力矩混淆、宽板可观测性。

- **run4（等效 CoP/面接触）**：宽刮板压在背上是"一片接触"，单腕 6D 力矩是**欠定**问题——最多反推"等效压力中心 CoP + 合力 + 残余力矩 + 偏载"，**不能还原整片压力分布**。第一版接触状态收敛为 5 元组。五个方法家族：CoP/面接触可观测性、Caron 力矩锥安全特征、MLS/DeepFit 局部法向、离散导纳冲击稳定性与 FR5 实验矩阵、RegHEC 标定-配准。

- **run5（摩擦/软刚度/异质接触）**：滑刮时摩擦会污染力矩——μ=0.3 时法向误差就约 16.7°，足以刮伤皮肤。三家族：摩擦感知法向（Nasiri 2024 用"力+速度"分离摩擦、已实机；Huang 2023 学习映射）、软组织刚度在线辨识（Hunt–Crossley + 卡尔曼族）、刚-软异质接触 EKF+MPC（Zheng 2025）。主线：接触状态相关的**动态融合权重**。

- **run6（人体背部 baseline）**：Zhai 等 2026 已在硅胶模型+健康志愿者背部，把"力觉接触点/法向估计 + 动态减速 + 力误差补偿 + 有界变阻抗"集成进同一闭环，是刮痧机器人**直接对照 baseline**。我们抄其"接触感知—控制状态机耦合"骨架，补宽板 CoP、摩擦感知法向、Eye-in-Hand 先验；并前置 KWR75D 腕部标定层、固定七状态双向刮痧状态机与四层安全。注意：真人实验只是可行性验证，非疗效证据。

- **run7（全链路 + 四层架构）**：打通"扫描→网格→法向→B-spline→SLERP"全链路；最关键一课是**腕部力传感器读数 ≠ 真实接触力**，必须过"零漂 + 惯性 + 蠕变"净化层（0.02–0.03 N·m 残差就足以误判板偏）；系统明确分四层（Geometry → Tool-wrench observer → Contact estimator → Controller）。RL 只做高层 wrench 自适应，不替代底层。

- **run8（画线→3D 轨迹）**：补最前端协作接口——人画的线怎么变成机器人能走的 3D 轨迹。核心结论：别做"逐像素读深度"的脆弱做法，而用"RGB 表达意图 + 局部曲面提供几何 + 曲面约束优化"三步走；两条 2D↔3D 映射 baseline（LSCM/重心坐标、点云贴面曲线）+ Eye-in-Hand 前视绕开遮挡。红线：力控可补毫米级几何误差，但不能掩盖手眼/TCP 系统误差。明确宽板单腕 6D 只能估等效 CoP/合力+偏载。

- **run9（人体按摩 baseline + 安全层）**：找到真人按摩里"RGB 画线→深度反投影→B-spline→ICP 动态更新"的直接 baseline（Xu 2024）。两大升级：① 用"局部曲面约束"作主约束，深度补全网络只辅助、低置信就暂停而非瞎编；② 补 energy-tank 安全层（任何自适应只输出候选参数，须经能量池 + 速率限制 + 力/速硬限）。边界：宽板 partial slip 依赖接触斑内部分布，腕部 6D 合力估不清，第一阶段只输出 CoP/偏载/摩擦利用率。

- **run10（运动环瓶颈 + 收尾）**：刮痧"刮不稳"未必是软件没调好，而是机械臂底层**运动环延迟造成相位滞后**（超声论文显示导纳相位滞后可达 121°，显式力控仅 5.76°）。强参照：IJRR 2026 动态机器人超声的显式力/力矩控制 baseline；软体"标准几何 + 实时形变"双层表示（比刚性 ICP 更贴合呼吸/受压）。机械被动柔顺可作 Plan B。收尾指向下一步：FR5 频域力跟踪/时延辨识与局部 non-rigid 背部更新。

- **run11（动态接触框架 + 运动环实测）**：弧形超声探头滚动时，真实接触位置会沿工具表面移动；新预印本将接触点与 interaction frame 在线更新。对刮痧板应迁移“接触点是时变量”的控制结构，但不能照搬超声图像接触检测。显式力/力矩控制在另一套医疗机器人上大幅改善动态力跟踪，提示 motion loop 可能限制导纳，却不是 FR5 的实测结果。下一步优先做 FR5 的命令—运动及目标力—实测力频响、动态 CoP 误差与离散导纳/jerk limiter 对照。

---

- **run12（接口与 baseline 审计）**：先区分供应商 SDK、ROS 2 service 包装与标准 ros2_control 硬件接口；API 返回成功不等于 F/T 数据有效，必须逐轴独立激励并使用独立参考载荷。固定参数导纳作为简单 baseline，自适应导纳作候选强基线，显式力控只在 FR5 接口确实支持时才算可实现对照。项目级 Gate、接口约定和实验路线见 [project_roadmap.md](../project_roadmap.md)。

## 五、贯穿全项目的"尚未解决"清单（跨轮汇总）

这些坑在多层反复出现，是需要你后续实机实验亲自验证的：

1. **宽刮板压力分布不可唯一还原**：单腕 6D F/T 只能稳估等效 CoP + 偏载，还原整片是数学上不可观测的（run4/run7/run8/run9 反复确认）。
2. **摩擦 vs 姿态失配 vs 组织被推走，三者力矩混淆**：滑动时残余力矩到底代表哪种，还分不清（run5/run7）。
3. **FR5 运动环延迟/抖动是硬瓶颈**：导纳外环频率被它卡住，真实稳定域未知（run7/run10）。
4. **软组织在线参数（刚度 K_e、摩擦 μ）待台架实测**：纸面模型不等于真人背（run5/run6）。
5. **KWR75D 轻载信噪比与长期蠕变未实测**：2–10 N 区间是否够用存疑（run6/run7）。
6. **误差预算没算清**：人工画线→3D 轨迹的总偏差，该修相机、修线检测还是修手眼标定（run7/run8）。
7. **动态接触框架与 wrench/Jacobian 参考点更新未验证**：接触点变化时位置、速度、姿态和力矩的参考点必须一起更新；符号、坐标系与时间对齐需要已知力臂工装实测（run11）。
8. **FR5 软件/传感器数据链尚未过 G0**：固件与 SDK tag 必须匹配；F/T 数据须做六轴独立响应、单位/符号、重复帧与独立参考测试；service API 的存在不代表实时性（run12）。
