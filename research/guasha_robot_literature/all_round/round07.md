# 第7轮：真实曲面刮痧全链路 + 腕部力矩到板端 wrench 的补偿 + 四层架构

> 学习目标：看懂从"相机扫出曲面"到"刮板真正贴着背刮"的完整链路，理解为什么腕部传感器读数必须层层净化才能用，并记住系统要分成四层来搭——这是后面所有实机代码的骨架。

## 1. 这一轮在解决什么问题（为什么重要）

上一轮（run6）我们已经在真人背上做了一次"基线"尝试——能扫、能压、能刮，但那更像是"先跑通看看"。这一轮要回答一个更尖锐的问题：**从相机看到背，到刮板稳稳贴着背刮，中间到底要过几道关？** 更重要的是，我们发现一个被低估的隐患：装在手腕的力传感器（KWR75D）读出来的数，根本不是刮板真正作用在皮肤上的"力"。如果直接拿这个数去算力度、算板压偏了没，后面所有判断都会错。所以这一轮把"真实曲面刮痧的完整链路"和"传感器读数净化"同时打通，并顺手把系统明确分成四层。这比把力数据处理当成"传感器小细节"要靠谱得多，因为力矩偏一点，后面推"板压偏哪了"就全歪了。

## 2. 前置小知识（本论用到、读者可能不懂的概念）

- **wrench（工具端广义力）**：一句话定义——同时描述"推了多重"和"拧了多大劲"的一组 6 个数（3 个力 + 3 个力矩）。生活比喻：快递包裹不只报"重 5 公斤"，还报"重心偏左、容易翻"，这俩合起来就是 wrench。在刮痧里：它指刮板作用在背上的"整体力学状态"，比单看一个压力数字全得多。

- **零漂（zero drift）与蠕变（creep）**：一句话定义——传感器明明没受力，读数却自己慢慢飘、甚至随时间越偏越多，是两类系统误差。生活比喻：厨房电子秤没放东西却显示"20 克"，而且放着放着变成"35 克"。在刮痧里：KWR75D 不动时也会悄悄偏，若不处理，会假装"板压歪了"。

- **牛顿–欧拉动力学补偿**：一句话定义——根据工具的质量、重心和当前加速度，算出"工具自己晃动产生的假力"，再从读数里减掉。生活比喻：你手里举着一碗汤走路，汤晃出来的力不是你压桌子的力，得先扣掉。在刮痧里：刮板转弯、急停时自身惯性会骗过传感器，必须扣掉才得到真实接触力。

- **误差预算（error budget）**：一句话定义——把"最后总误差多少"一层层拆开，看每步（拍照、测距、标定、拟合）各贡献多少。生活比喻：快递迟到 1 天，拆成"分拣 2 小时 + 堵车 18 小时 + ……"，才知道该罚谁。在刮痧里：人工画线变成 3D 轨迹，总差 4 毫米，到底该修相机还是修算法，靠预算判断。

- **四层架构**：一句话定义——把复杂系统切成"感知→净化→估计→控制"四块，各管各的。生活比喻：餐厅分"点单→后厨备料→炒菜→上菜"，不混在一起。在刮痧里：我们不能把脏力数据直接喂给控制器，必须过四层。

- **可观测性（observability）**：一句话定义——系统能不能从有限的传感器读数，唯一反推出内部真实状态，反推不唯一就叫"不可观测"。生活比喻：蒙眼摸一个黑盒，只给一个弹簧秤，你永远猜不出盒子里是几块砖、怎么摆——这就是不可观测。在刮痧里：宽刮板整片压力分布无法由单个腕部六维 F/T 唯一还原，正是 3.5 节说的"不可辨识"，所以第一版只报等效量，别贪心去恢复整片。

## 3. 核心内容讲解（逐步、通俗，多用类比）

### 3.1 全链路：从"扫"到"刮"怎么走完（几何家族）

这一轮找到一篇 2026 年最直接的"曲面刮削"论文（He 等，Aerospace）。它的链路非常干净，我们几乎能照抄数据结构：

**它在干什么**：先用激光/相机扫出真实曲面 → 拼成网格（mesh）→ 在每个点算出局部"法向"（垂直于表面的方向，见术语表）→ 生成刮板该摆的位姿 → 位置用 B-spline 连成顺滑曲线（见术语表，像软尺按图钉弯出弧）→ 姿态用 SLERP 平滑过渡（见术语表，像方向盘匀速转）。最后自动刮完，比人工快一倍（自动约 40 分钟，人工 80–100 分钟）。

**为什么聪明**：它不像我们早期那样"逐点硬塞姿态命令"，而是对法向先做滤波、姿态做限速，否则相机法向噪声会直接变成"力度忽大忽小"。

**我们能抄什么**：把"人工画线"精确定义成只负责产生背上的中心线 Γ(s)（s 是沿线的弧长，见术语表）——曲面几何自动补法向 n(s)，再结合刮板的工艺倾角 β 生成最终姿态 R_scraper(s)。一句话：**人画道，机器补法向和倾角。** 这正好和 run6 的"人工标线"接上。

> 比喻：把后背想成凹凸不平的瑜伽垫，上面画了要刮的"主干道"。相机眯眼一看，只能估出垫子鼓哪儿凹哪儿；真正的"垂直往里推"方向（法向），得靠算法在每点替你算。人只管画直线，机器补"垂直压的方向"和"板歪多少度"。假如你是调试工程师：第一天拿到点云，先戳中心线，盯法向是否大致垂直皮肤，再让 B-spline 连顺、看有没有突然打弯；若法向东倒西歪，说明相机噪声没滤净，直接刮必力度忽大忽小——所以论文先滤波再限速，顺序不能反。

### 3.2 腕部力矩到板端 wrench：必须净化的"脏数据"（力估计家族）

这是本轮最关键的一课（Wen 等，Sensors 2025）。

**它在干什么**：腕部 F/T 传感器读到的数，真实长这样——传感器读数 = 真实接触 wrench + 重力 + 工具自身惯性力 + 初始零漂 + 蠕变 + 噪声。如果只做"减重力"就直接拿去算力度和板偏，等于用带偏的尺子量血压。作者用牛顿–欧拉模型在线辨识工具质量/重心/惯量，再用一种叫 SNN 的神经网络补偿蠕变，把脏读数净化成可信的板端 wrench。实机力误差 < 0.5 N、力矩误差 < 0.03 N·m。

**为什么聪明**：它证明 0.02–0.03 N·m 的力矩残差，就足以让你误判"板左边翘了还是右边翘了"。净化后，遇到障碍 0.02 秒就柔顺让开再回力。

生活比喻：这就像用天平给病人称药，砝码本身悄悄歪了 0.02 克，你会把"该加半片药"误判成"药量正好"——误差绝对值虽小，结论却可能完全反向。刮痧板边只靠 0.02–0.03 N·m 的残余力矩来区分"左翘还是右翘"，这点数一旦被零漂和惯性吃掉，方向判断就整个翻过来，所以净化必须在这之前完成。

**我们能抄什么（最小实现）**：第一版不用抄 SNN，先做到——多姿态静态标定质量/重心/零漂 → 已知加速度时扣掉惯性力 → 低速高速两组对比 → 独立台架加载验证 → 验证过后才敢用这数去推 CoP 和法向。尤其要在转弯/U 型回刮时单独测，因为那时姿态和加速度变化最大。

### 3.3 四层架构：为什么不能把 F/T 当"小细节"

**它在干什么**：把软件明确切成四层——① Geometry（D435 相机出中心线、法向、曲率、置信度）；② Tool-wrench observer（KWR75D 原始 → 净化后的 wrench）；③ Contact estimator（用净化 wrench + 法向 + 速度 + 板几何，估出法向、压力中心 CoP、偏载、摩擦态）；④ Controller（切向轨迹 + 法向柔顺 + 姿态平滑 + 安全监督）。

**为什么聪明**：把"传感器预处理"从可有可无的小事，升级为独立一层。因为力矩偏置会直接污染最核心的 CoP/姿态估计——脏东西早滤掉，比后面补救强。

**我们能抄什么**：实机代码就按这四层建文件夹，层与层之间只传干净接口。推荐的研发顺序也变了：先证明 wrench 可信 → 再推 CoP/偏载 → 再结合视觉推法向 → 最后才做柔顺刮痧，而不是一上来就搞视觉–力觉融合。

> 比喻：这四层像做菜——① 买菜（几何，拿原料和形状）、② 洗菜去泥（wrench 观测，冲掉脏东西）、③ 尝味判咸淡（接触估计，知板压得对不对）、④ 掌勺上桌（控制，真去刮）。把"洗菜"省了，泥直接进锅，后面再怎么掌勺都救不回。所以 run7 坚持把"洗菜"单独立层。

### 3.4 学习只做"高层 wrench 自适应"（RL 后置，家族旁支）

本轮还发现一篇支持我们策略的论文（Cetin 等，2026）：底层永远用稳定的阻抗控制保接触，RL 只在高处调"目标 wrench 该加减多少"，sim-to-real 后五种材料平均提升 10.9%。

**为什么聪明 / 我们能抄什么**：以后若上 RL，接口应是"给一个力/参数的修正量"（比如 ΔF_d、ΔM_d、ΔD_d），而不是直接让 RL 输出机器人怎么动。底层安全控制独立存在，学崩了也不会伤人。这再次印证我们"RL 后置而非替代底层"的路线。

> 假如你是调试工程师：将来塞 RL 模块，记住它只能动"旋钮微调档"——告诉底层"目标力加 0.3 N、阻尼松一点"，而非自己掰电机。底层阻抗控制是安全护栏，RL 再胡学，最多力调得不舒服，绝不会把板子捅进肉里。就像实习生只调空调温度，不能碰总电闸。

### 3.5 宽刮板接触的"不可辨识"提醒（接触估计家族）

ICRA 2025 的 CDM 论文点破：多个接触点/力组合可能产生同一个传感器读数（多解）。它提醒我们：**一个腕部六维 F/T 不足以还原刮板整片压力分布。** 第一版老老实实估"等效 CoP + 残余力矩 + 偏载态"，别吹能恢复完整压力线。上轮 Zheng 等的工作（EKF 联合估刚度/摩擦并进入 MPC）也说明，第二阶段可扩展到估 [n, p_CoP, K_e, μ]，但第一版不该同时估全部状态。

> 比喻：闭眼单手按一块宽海绵，只靠手腕一个力传感器，你只能感到"整体往哪推、有没有拧劲"，却永远猜不出海绵上每点是均匀受力还是左重右轻——数学上就多解。所以第一版只老老实实报"等效中心 + 残余力矩 + 偏载程度"三项，不贪心吹能画整片压力云图。

## 4. 关键算法/公式的直觉（大白话）

- `W_sensor = W_contact + W_gravity + W_inertia + b0 + b_creep + noise`：传感器像被好几股力同时拽的弹簧，只有 W_contact 是想要的"真接触"，其余都是伪装，净化就是把伪装一个个扣掉。可把它想成一锅汤里混了盐（重力）、味精（惯性）、过期料（零漂蠕变）和灰尘（噪声），我们要的只是"汤本身的鲜味"（真实接触力），其余都得撇掉。

- `W_raw → bias/CoG → 惯性补偿 → 低通滤波 → W_tool`：原始数据先去零漂和重心偏，再扣自身惯性，最后平滑去抖，出来的 W_tool 才进下一步。就像洗照片：先去划痕（零漂）、校正偏色（重心）、扣手抖的糊（惯性）、磨掉噪点（滤波），一张能看的照片才出来。

- `q_i = {s_i, p_i, n_i, R_i, Fd_i, vd_i, state_i}`：每个轨迹点带"走了多远、在哪、法向朝哪、板怎么摆、目标力、目标速度、当前状态"，像给刮板写一份带备注的行程单。好比外卖小哥每到一个路口记"已走 200 米、在 A 巷口、面朝东、车把斜 15 度、目标时速 20、现在等红灯"——导航或复盘都靠这张单子。

- `R_scraper(s) = R_n(s) · R_β`（板姿态 = 法向旋转 × 工艺倾角旋转）：先让板面"垂直对准皮肤"（法向旋转 R_n），再整体歪一个工艺角 β（比如板头略抬便于推刮），两步叠加才是最终握姿。好比握方向盘：先对准"垂直路面"的方向，再按手感整体歪一点；别一步直接掰到终点，容易歪错方向还回不来。

## 5. 仍然没解决的坑 / 局限（2–4 条）

1. KWR75D 在 2–10 N 轻载下的力矩信噪比和长期蠕变还没实测，纸面漂亮不代表实机稳。
2. FR5 伺服的指令到动作延迟/抖动会卡住导纳外环频率，真实瓶颈未知。
3. 软组织滑动时，残余力矩到底代表"板歪了、摩擦变了、还是组织被推走"，三者还分不清。
4. 人工画线从照片到 3D 轨迹的总误差预算还没算，不知道该修相机、修线检测，还是修手眼标定。

## 6. 这一轮你该记住的 3 件事

1. 腕部力传感器读数 ≠ 真实接触力，必须过"零漂 + 惯性 + 蠕变"净化层，否则后面全错。
2. 系统要分四层（几何 → wrench 观测 → 接触估计 → 控制），脏数据早滤比补救强。
3. 宽刮板接触不可完整还原，第一版只估等效 CoP + 偏载，别贪心声称恢复整片压力。

## 7. 和前后轮的关系

- 承接：run6 在人体背部做了 baseline（能扫能压能刮的雏形）；这轮把它升级成"从扫到刮"的完整链路，并补上 run6 忽略的力数据净化问题。具体说，run6 让机器人"勉强刮了一次"却默认腕部读数可信；run7 一上来泼冷水——那读数不能直接信，于是把雏形拆成几何、净化、估计、控制四块重搭，相当于给毛坯房做水电改造再装修。

- 铺垫：为 run8 埋了三颗种子——① 人工画线→3D 轨迹的逐级误差预算（e_total = 分割+深度+手眼+配准+曲面投影+样条）；② FR5 的 sampled-data/无源性可计算稳定条件（找 Ts、delay、Ke、Md、Dd 的关系）；③ 宽刮板软接触 CoP/残余力矩的可观测边界实验。这三块最可能是属于我们自己的算法贡献。
