# 第6轮：直接在人体背部做同构 baseline——接触点/法向估计 + 动态减速 + 力误差补偿 + 有界变阻抗

> 学习目标：读完这一轮，你会明白"在真人背上做刮痧机器人最该抄哪篇现成方案"，以及为什么我们要把"腕部传感器标定"当成第一道工程关。你将理解一套把"接触感知"和"柔顺控制"串成一个闭环的方法家族，并知道我们自己的创新边界落在哪里。

## 1. 这一轮在解决什么问题（为什么重要）

前几轮我们一直在"纸上谈兵"：run5 研究了摩擦、软刚度、异质接触的估计**理论**，但那些结论大多来自工厂抛光、打磨，或者硅胶假人。这一轮我们要回答一个更实在的问题——**能不能直接在"真人背部"上，把这套"看得清曲面、摸得清力、刮得稳"的链路跑通？**

答案在本轮出现了一个关键突破：2026 年 8 月刚发表的一篇论文（Zhai 等，发表于 *Frontiers in Robotics and AI*）已经这么做了。它用机械臂 + 六维力觉传感器，先在硅胶人体模型上验证，随后在**一名健康志愿者的背部**完成了按压、拍打、揉捏、推动等初步实验。更重要的是，它把前几轮我们分开追的几块拼图——力觉接触点估计、在线表面法向估计、接触前动态减速、力误差补偿、可变阻抗——**集成进了同一个闭环**。

这件事为什么重要？打个比方：你准备照着一个菜谱做一道没人做过的菜。前几轮我们找到的是"切菜怎么切、火候怎么控"的零散技巧；而这篇论文相当于已经有人用同样的灶台、在类似的食材上，把整道菜做出来过一次。它就成了我们的 **baseline（对照照片）**——拿来作对比的"基础参照实现"。我们不必从零发明，而是可以站在它肩上，只改那些它没做、而我们刮痧特有的部分（比如宽刮板、人工画线、视觉先验）。同时，它也第一次把"创新边界"划清了：哪些已有强支撑、哪些还必须我们自己实验回答。

## 2. 前置小知识（本论用到、读者可能不懂的概念）

- **局部接触坐标系（local contact frame / local task frame）**
  - 一句话定义：在"刮板和皮肤真正贴住的那一小块地方"临时建立一个小小的坐标轴（法向朝外、切向沿表面），后续所有力与运动都按这个小小坐标系来算。
  - 生活比喻：你趴在桌上写字，桌面就是你的"局部坐标系"；无论整张桌子怎么歪，你只管相对桌面摆正纸和笔。
  - 在刮痧里：背上每一处都是弯的，机器人不拿"世界坐标"硬算，而是每到一处就建一个"贴着皮肤的小坐标"，法向压下去、切向刮过去。

- **力误差补偿（force-error compensation）**
  - 一句话定义：实时算出"目标力"和"实际力"的差，并主动把这个差补回去，让实际力稳稳贴近目标。
  - 生活比喻：你端着一杯快溢出来的水走路，感觉到水晃（误差）就下意识把手往反方向稳一下，把误差抵消掉。
  - 在刮痧里：目标压 10 牛，实际测到 12 牛，就立刻让臂往回松一点，把多出来的 2 牛误差补掉。

- **动态接近减速（dynamic approach deceleration）**
  - 一句话定义：机械臂不是一直高速冲到皮肤才急刹，而是在靠近的过程中**分阶段连续减速**，像踩点刹一样越近越慢。
  - 生活比喻：你伸手摸一个怕痒的人，不会"啪"地拍上去，而是手越靠近越慢，轻轻贴上。
  - 在刮痧里：避免板子高速撞上背造成冲击、或被反作用力弹得上下振荡。

- **有界变阻抗（bounded variable impedance）**
  - 一句话定义："弹簧软硬"不仅随情况在线调整，而且被**锁死在一个安全范围里**，不会突然变到极硬或极软。
  - 生活比喻：汽车减震器能调软硬，但厂家的调节范围有上限，不会让你调到"硬得像铁、一碰就弹飞"。
  - 在刮痧里：前刮时稍硬一点好出力，回程时软一点好贴服；但无论怎么变，都被"有界"这把锁限制在安全区间内。

- **腕部 wrench 前处理标定层（KWR75D payload/CoG/bias calibration）**
  - 一句话定义：在让传感器数据进任何算法之前，先把它自身的"体重、重心、零偏"减掉、并转到正确坐标系、再滤波，得到干净的接触力。
  - 生活比喻：你称体重前得先"清零"——把秤上拖鞋的重量扣除，否则读数全是错的。
  - 在刮痧里：刮板自身有重量和重心，姿态一变就产生重力矩；不先标定，板子自己重量会被误判成"皮肤被压的反作用力"。

## 3. 核心内容讲解（逐步、通俗，多用类比）

### 3.1 主链：Zhai 2026 的"接触—控制"闭环

这篇 baseline 论文最聪明的地方，是**不把"建立接触"和"保持恒力"当两件事割裂**，而是串成一条链：

`按摩技能轨迹 → 力觉估计接触点+法向 → 更新局部坐标系 → 动态接近减速 → 力误差补偿 → 有界变阻抗 → 机器人动作`

我们逐段翻译它在干什么：

- **力觉估计接触点+法向**：它先补偿工具重力/重心对力觉的污染，再根据"力+力矩"反推出板子此刻贴在背上哪一点、表面朝哪（法向）。为什么聪明？因为它**不依赖皮肤表面法向固定不变**——背上本来就是弯的、软的，它靠手感（力觉）实时猜。
- **更新局部坐标系**：上面 2 里说的"贴着皮肤的小坐标"就这样随接触点、法向实时刷新。
- **动态接近减速**：如 2 所述，分阶段慢下来贴上去，避免冲击和之后上下弹。
- **力误差补偿 + 有界变阻抗**：接触建立后，持续用"目标力 vs 实际力"的误差去微调，同时让弹簧软硬在安全范围内随阶段变化，维持稳稳的恒力贴面。

**我们能抄什么**：不是照抄它的"按摩技能学习"（DMP），而是抄它的**骨架**——"接触状态估计"和"控制状态机"必须耦合在一起，而不是各管各的。我们把自己的"人工画线 3D 轨迹"塞进它的 DMP 位置，再补上我们特有的宽刮板 CoP、摩擦感知法向、Eye-in-Hand 视觉先验。

### 3.2 法向不能简单用"合力方向"——摩擦感知估计

这里埋着 run5 理论的一个直接落地。当刮板在背上**滑动**时，切向摩擦力很大，此时"合力方向"会被摩擦拽偏，不能直接当成真实法向。本轮交叉证据很强：Nasiri–Wang 2024 明确指出，要用 `力 + 运动速度` 一起反推法向，而不是令 `n = 力/力的大小`。

打个比方：你在湿滑斜坡上推一个小车，你用的劲（合力）是斜着的，但坡面的"正对面方向"（法向）是另一个方向。你光看使了多大劲，猜不出坡面朝哪；必须把"车实际往哪滑"也考虑进来，才能还原坡面方向。刮痧里，**前刮状态**板在滑，就必须用"力 + 速度"联合估计，否则法向会歪、板会斜戳皮肤。

于是我们的融合器从简单的 `法向 = 视觉权重×视觉法向 + 力觉权重×力觉法向`，升级成"看当前在哪个状态、各路信号可信度如何"的智能融合（详见 4 的公式直觉）。

### 3.3 第一步不是控制，是"称体重"——KWR75D 标定层

这是本轮一个容易低估、但必须最先做的工程关。后面所有聪明的估计（接触点、偏载、法向、摩擦）都依赖腕部传感器原始的 `[力, 力矩]`。如果工具质量、重心、零偏没标定准，**板子自己重量产生的力矩会被误判成皮肤接触力矩**——地基就歪了。

本轮找到两个实用的 ROS2 开源实现（ft_tools_ros2、end_effector_mass_estimation），它们用约 10 个不同静态姿态，通过最小二乘同时辨识出 `质量 m、重心 c、力零偏 f0、力矩零偏 τ0`，随后做重力/零偏补偿、坐标变换、死区与低通滤波。建议把这一层做成**独立的 ROS2 节点**，像"进车间先洗手"一样，任何接触算法之前都先过这道关。

### 3.4 双向刮痧状态机（七个状态）

刮痧不是"一路刮到底"，而是要**前刮用力、回程收力再返回**。本轮正式固定了一套七状态机：

`接近 Approach → 触碰 Touch → 力爬升 Ramp → 前刮 ForwardScrape → 转弯 Turn → 轻力回程 LightReturn → （再 Turn 回到前刮）`

每个状态不再是简单"走到某点"，而是各调一组参数：`目标力 F_d、目标速度 v_t、视觉-力觉融合权重、弹簧软硬（M_d/D_d/K_d）`。比如：
- **接近**：视觉主导，力为 0，速度逐步降；
- **触碰**：检测"贴上了"，限制冲击；
- **力爬升**：力从轻到重平滑升到刮痧力度（S 曲线，不突兀）；
- **前刮**：用力+切向轨迹，启用完整摩擦感知估计；
- **转弯**：切向速度趋 0，降低力觉法向权重，姿态连续过渡；
- **轻力回程**：力远小于刮痧力，因传感器信噪比下降而提高视觉权重。

它就像一个"会看路况自动调挡"的司机，不同路段用不同挡位和力度。

### 3.5 安全层升级：从"只看力"到"四层安全量"

原来的安全逻辑往往只是 `法向力 < 最大力` 这么一个阈值。本轮受 Wan 等 2026 启发，建议升级成四层：

`力上限 + 速度上限 + 偏载/CoP 上限 + 交互能量/passivity（无源性）`

尤其最后一层：监视交互能量 `E(k) = E(k-1) + 力^T × 速度 × 采样周期`。打个比方，给它装个"能量账户"，只允许取用不允许透支，一旦能量异常飙升（说明系统快乱了），就限力回撤。这比单看力更能在"刚度突变"时防暴冲伤人。

### 3.6 其他补充（先记着，不必改结构）

- **机械柔顺末端**（Shin 等 2025）：在臂尖加一段真弹簧/弹性关节，能显著缓解冲击、降低对软件带宽的压力。当前第一代原型**先不改硬件**，但可作为二代设计变量——好比先试"软件调速"，真不行再加"物理减震器"。
- **点云上采样**（PLATYPUS, AAAI 2025）：把稀疏嘈杂的 3D 点云在肩胛、脊柱等高曲率处补得更密。它不适合塞进 100 Hz 高速控制环，但适合做"慢速背部重构层"。

## 4. 关键算法/公式的直觉（大白话）

**① 腕部标定模型**（为什么要"称体重"）：
- `f_meas = -m·g + f0`：传感器实测力 = 负的"工具重量朝下" + 零偏。
- `τ_meas = -m·c×g + τ0`：实测力矩 = 负的"重心×重力"产生的力矩 + 零偏。
- 直觉：把 m、c、f0、τ0 算准并减掉，剩下的才是"皮肤给你的反作用力"。这就是"清零秤"的数学版。

**② 状态相关的法向融合器**：
- `n_hat = Estimator( n_v, F, τ, v_t, p_CoP, state )`
- 直觉：法向估计不再是两个数加权那么简单，而是把"视觉法向 n_v、力 F、力矩 τ、切向速度 v_t、接触点 p_CoP、当前状态 state"全喂进一个估计器。关键在 `state`——前刮时力觉丰富就多信力觉，转弯/轻力回程时力觉变差就多信视觉。`state` 决定了各路证据的"话语权"。

**③ 交互能量监视**：
- `E(k) = E(k-1) + F^T(k)·v(k)·T_s`
- 直觉：每一步把"力×速度×时间间隔"累加进能量账户。力大且动得快，能量涨得快；一旦发现涨得太猛（系统要失稳），就触发安全回撤。这是对"无源性"最朴素的理解——系统不能自己凭空加能量。

## 5. 仍然没解决的坑 / 局限（2–4 条）

1. **真人实验只是可行性验证，不是疗效证据**。那篇 baseline 只在 1 名健康志愿者背上做了初步安全/可行性测试，样本极小、且明确说不是临床疗效。所以我们早期论文目标应写成"接触控制、几何/力觉估计与安全性能"，**不要**声称医学疗效。
2. **宽刮板 vs 点状接触**。baseline 用的是"点状/拇指式"工具，而我们的刮板是**有宽度的线/面接触**，等效接触点（CoP）会偏移。它能否稳定区分"板子姿态倾斜"和"皮肤被剪切/局部凹陷"，还需自己实验。
3. **轻力回程时传感器信噪比**。KWR75D 在回程力很小时，力矩信噪比可能不足以支撑 CoP/姿态失配估计——这也是为什么回程要改靠视觉补。
4. **FR5 实机延迟仍是瓶颈**。底层伺服的 command-to-motion 延迟、抖动、可持续控制频率，必须实测才能定第一版导纳参数；论文里的时间延迟补偿（Oh 等 2026）先作为"以后对照方法"，不直接堆上去。

## 6. 这一轮你该记住的 3 件事

1. **真人背部已有可直接抄的 baseline**：Zhai 2026 把"接触点/法向估计 + 动态减速 + 力误差补偿 + 有界变阻抗"集成验证过，我们的创新边界因此清晰——抄骨架、补宽刮板与视觉先验。
2. **任何接触算法之前，先过"腕部标定层"**：工具质量/重心/零偏不补偿，后面全错；把它做成独立 ROS2 节点。
3. **感知与控制必须"按状态融合、按状态切换"**：前刮信力觉、转弯/回程信视觉，状态机调度的是一整组力/速/软硬/权重参数，而不是单点路径。

## 7. 和前后轮的关系

- **承接：run5 留下什么，这轮接上。** run5 研究的是摩擦、软刚度、异质接触的**估计理论**；本轮把这些理论"落到真人背部"这个最直接可复现的 baseline 上，并用 Nasiri–Wang 的摩擦感知法向把 run5 的"滑动会污染法向"直接变成工程解法。KWR75D 标定层也补上了 run5 隐含却未单独强调的"传感器前处理"工程关。
- **铺垫：为 run7 埋了什么伏笔。** 本轮正式固定了"双向刮痧七状态机"与"状态相关的局部接触坐标系估计器 `x_c = [法向, 接触点, 法向力, 切向力, 残差力矩, 接触置信度]`"，并区分了视觉慢层（几何先验）与 F/T 快层（力觉）。这恰好为 run7 的"真实曲面 scraping 全链路（scan–mesh–normal–B-spline–SLERP）"与四层架构（感知/估计/控制/安全）搭好了接口与分工框架。
