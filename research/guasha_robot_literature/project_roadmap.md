# 刮痧机器人项目路线图：系统分解、算法难点与调研纠偏

> 版本日期：2026-10-10  
> 目标：把长期文献追踪从“搜集可能有用的算法”收敛为“可验证、可集成、可安全退化、可复现实验的完整机器人系统”。  
> 使用方式：每轮研究开始先读本路线图与最近两轮报告；结束时更新问题优先级、证据状态和验收进度。

## 0. 项目成功的定义与边界

本项目的近期目标不是证明刮痧的临床疗效，也不是直接让学习策略控制机器人，而是构建并验证一个**有明确使用边界的机器人接触操作系统**：

- 操作者给定背部目标区域与一条/多条 2D 刮拭路线；
- 系统将意图转换为有置信度的 3D 曲面轨迹；
- 机器人通过已标定的刮板工具和六维力觉实现可控的贴面接触、前向刮拭、轻力回程与安全退出；
- 人体/体模轻微移动、软组织形变、摩擦变化或控制延迟出现时，系统能够检测误差、减速/暂停/退出，而不是静默地继续执行错误轨迹；
- 通过有参考真值、对照基线、故障注入和可重复日志证明每个子模块及端到端链路的性能。

使用范围、安全力/压力/速度/暴露时间、工具边缘与皮肤风险、允许的人体实验条件，都必须由项目负责人、具有相应资质的临床/理疗顾问和安全负责人共同确定。不能从其他机器人论文的探头力或抛光参数直接推导适用于刮痧的人体安全设定值。标准的适用性也取决于预定用途；例如 ISO 13482 针对个人护理机器人及人体接触安全，但官方范围明确排除作为医疗器械的机器人，不能未经用途分类就声称满足该标准。

## 1. 完整系统拆分与依赖关系

推荐的主链路：

`使用边界/安全需求`
→ `FR5 与传感器接口、时间同步、坐标标定`
→ `RGB-D 曲面与 2D 标线到 3D 轨迹`
→ `工具 wrench 观测与动态接触状态估计`
→ `沿轨迹的切向运动 + 法向柔顺/力控制`
→ `前刮/转向/轻力回程状态机`
→ `独立安全监督与端到端验证`

局部非刚性重建与 residual/offline RL 是可后置升级的分支，不能作为第一版系统的前提。

### 模块 A：任务定义、风险分析与安全边界（整个项目的前置条件）

**要回答的问题**
- 机器人用于研究演示、个人护理还是医疗用途？对应的风险分析与法规/标准路径是什么？
- 皮肤接触的力、压力、速度、温升/摩擦、工具边缘、持续时间、重复次数，哪些指标需要硬限制？
- 哪些故障必须立即停机，哪些可以减速/轻力回撤？
- 谁能启动任务、谁能确认目标区域、谁能触发急停与解除故障？

**必须产出的内容**
- system requirement/specification；
- 以工具与人体接触为核心的 hazard analysis/FMEA；
- 操作包络与禁用场景；
- 独立于规划/学习算法的安全监督逻辑；
- 体模测试、人体可行性研究的伦理/审批与停止标准。

**算法/工程难点**
- 不能把普通碰撞安全等同于持续刮拭安全；切向摩擦和刀/板边缘压力可能比单纯法向力更关键。
- 不能把软件阈值当成机器人安全认证；需确定实际停止距离、停机路径、控制器饱和与通信中断的行为。
- 任何法向估计、接触置信度或时间戳异常都要有确定的安全降级路径。

### 模块 B：机器人接口、标定与同步的“真实世界基准”

这是所有几何与力控算法的共同前提，必须排在高级算法前面。

**坐标与标定**
- `base ↔ flange ↔ camera`：Eye-in-Hand 手眼标定以及机器人运动学坐标链；
- `flange ↔ F/T sensor ↔ scraper`：传感器到刮板的刚性变换、工具几何、质量、重心；
- `scraper ↔ contact`：板面、刃口、候选接触线/区域与等效 CoP 的几何关系；
- 统一表达每一个变换的方向约定、单位、时间戳和版本。

可作为标定基准的工作包括 Hydra（marker-free RGB-D hand-eye，公开代码/数据和 ROS 2 集成）；但论文报告的任务空间误差并不自动等于本项目的精度，仍要用自己的刚性工装验收。官方 ROS 2 导纳控制器也要求可用的运动学插件、wrench 输入和兼容控制接口；它不是无需适配就能运行在任何 FR5 SDK 上的即插即用方案。

**wrench 观测器**
- 去除传感器 bias，并估计工具重力/重心引起的姿态相关 wrench；
- 检查温漂、零漂、滤波延迟、动态惯性项与长期蠕变；
- 明确传感器输出坐标系与力矩参考点；
- 将 wrist wrench 变换到目标工具/接触参考点时，不能只旋转力与力矩而忽略参考点平移。

若 `r_EC` 表示从末端参考点 E 指向接触参考点 C 的向量，且向量与 wrench 已采用一致坐标表达，则参考点变换有 `tau_C = tau_E - r_EC × F`；实际实现必须用已知力臂加载单元测试校验符号、坐标和量纲，并按完整的六维 wrench 变换处理。

**时间同步与运动环辨识**
- 为 robot pose/joint state、F/T、RGB-D、命令和控制器状态建立统一时间基准；
- 测量命令到实际运动的延迟、反馈延迟、抖动、有效刷新率、丢包/队列行为；
- 区分“算法计算慢”和“机器人底层伺服慢”；
- 用安全的小幅正弦激励测 `command → motion`，并在可控软垫上测 `force target → measured force` 的幅值与相位。

**验收产物**
1. 坐标链图与 calibration manifest；
2. 手眼/TCP/工具接触几何误差报告；
3. wrench 参考点与重力补偿单元测试；
4. 控制/传感时序日志和延迟分布。

### 模块 C：人体曲面感知与“2D 意图 → 3D 曲面轨迹”

直接相关的基线已经存在。Xu et al. 2024 在真实机器人按摩中实现了操作者于 RGB 图像画 2D 曲线、深度反投影、B-spline 轨迹、刚性点云配准更新和混合运动/力控制；因此本项目应复现为 baseline，而非把基本的 2D→3D 画线流程宣称为全新贡献。

**第一版建议链路**

`RGB 标线分割`
→ `有序 2D polyline`
→ `深度可靠性掩码`
→ `局部点云/曲面 patch`
→ `射线—曲面交点或最近表面投影`
→ `曲面约束平滑`
→ `弧长重采样`
→ `位置/切向/法向/姿态/置信度`

**算法难点**
- 彩色标线、反光皮肤、斜入射、低纹理、深度洞与板遮挡会让逐像素反投影不可靠；
- PCA/MLS/mesh 法向存在邻域尺度、离群点、符号方向和曲率变化问题；
- B-spline 平滑可能使轨迹离开真实曲面；必须加入 surface consistency；
- 2D 线条点按像素等距并不等于 3D 曲线按弧长等距；
- Eye-in-Hand 视野遮挡接触点时，需要看向刮板前方的 look-ahead 区域；
- 人体呼吸或姿势变化下，刚性 ICP 只能更新整体姿态，可能无法恢复局部形变。

**主次排序**
- P0：可复现的 RGB-D + 局部曲面投影 + B-spline/弧长基线；
- P1：动态局部 patch tracking、法向/曲率置信度与遮挡恢复；
- P2：DynamicSurf 等非刚性 RGB-D neural reconstruction 作为离线对照，只有在误差/延迟收益明确后才考虑部署到慢层；
- 不把 learned depth completion 直接当作皮肤真实几何或安全接触点。

**输出协议**
每个轨迹样本至少包含 `{s, p, t, n, R, confidence, timestamp}`，并能追溯其来源帧、标定版本和曲面局部模型。

### 模块 D：刮板工具模型与在线接触状态估计

这不是普通点 TCP 问题。宽刮板在皮肤上通常是线/面分布接触，腕部六维 F/T 只提供合力与合力矩；不能唯一恢复整片压力分布，也不能仅靠腕部 resultant wrench 保证识别局部 partial slip。

**第一版可解释状态**
`x_c = [F_n, F_t, p_CoP, e_edge, tau_residual, confidence]`

- `F_n)：当前估计局部法向上的合力；
- `F_t)：切向合力/摩擦相关分量；
- `p_CoP)：等效压力中心，不代表真实压力分布；
- `e_edge)：偏载/边缘负载风险特征；
- `tau_residual)：经过 wrench 变换、重力与 bias 补偿后的残余力矩；
- `confidence)：由传感器质量、工具几何、模型残差、可观测性与时间一致性综合得出。

**关键难点**
1. 单点接触、线接触和宽面接触不能共用一个未经说明的观测模型。
2. 力矩变化可能来自姿态误差、滑动摩擦、组织压陷、接触点移动或传感器残差，不能将所有力矩直接解释为“板歪了”。
3. 需要区分三种法向：视觉几何法向 `n_v`、实际承载/接触法向估计 `n_c`、刮板工具法向 `n_t`；只有通过估计/控制模型把它们关联起来，不能直接视为相等。
4. contact frame 随 CoP 更新时，位姿、接触点速度、wrench 力矩参考点、Jacobian 与控制误差必须一致更新。
5. 仅腕部 6D F/T 对分布接触存在结构性不可观测部分；若后续要研究 partial slip，需要分布式触觉/剪切传感或可验证的外部真值。

**有目的的文献选择**
- Arefin & Tiryaki, 2026-09-28 arXiv 预印本：演示接触定位与 interaction frame 的在线更新，但其独立接触证据来自超声 B-mode 图像，不能原样迁移到没有超声的刮板。
- Kutsuzawa & Hayashibe, IJRR 2026（2025-09-27 online first）：工具几何与接触位置的粒子滤波联合估计；因为本项目刮板几何已知，先做解析几何 + 时间滤波，不先引入高维联合工具形状估计。
- 这些工作用于提出可检验设计，不证明我们的 CoP/真法向估计已经有效。

### 模块 E：基础曲面跟随、恒力与姿态柔顺控制

**第一版应以可解释的经典闭环为主**：
- 切向：跟踪已生成的 3D 曲面路径，限速、限加速度/jerk；
- 法向：由力误差生成小幅受限位移/速度修正（admittance），或由机器人实际支持的 force interface 执行力控制；
- 姿态：用经过滤波的视觉法向与接触状态估计更新工具姿态，限制角速度/角加速度，避免被噪声带动快速旋转；
- 接触点/法向低置信或跳变时，先减速、冻结姿态更新、降低目标力或退出；
- 控制与安全限制分离：自适应参数也只能经过约束监督后下发。

连续时间导纳方程可以做直觉模型，但不能代替离散采样、通信延迟与机器人内环的稳定性验证。Mae & Kikuuwe 2024 的 jerk-limited、implicit-Euler 导纳在有约 6 ms deadtime 的 UR3e velocity-command 模式上进行了验证，可做算法对照；其时延不能当作 FR5 参数。Piedra et al. 的 IJRR 2026 显式力/力矩控制结果提示底层 motion loop 可能限制传统导纳，但只有当 FR5 的实际控制接口支持相应控制层级时，才可做直接方法对比。

**需要攻克的算法难点**
- 位置型机器人上的离散导纳与延迟稳定性；
- 视觉更新较慢、F/T 更新较快时的多率融合与时间对齐；
- 法向力、切向摩擦与工具姿态耦合；
- 硬限幅、速率限制、jerk 限制与能量/无源性监督之间的协调；
- 接触建立、转向和轻力回程的瞬态冲击；
- 失去接触、传感器饱和、命令超时或估计发散时的可验证退出策略。

**必要对照组**
1. 固定 TCP + 固定/视觉法向 + 基础导纳；
2. 同一基线 + 离散/jerk-limited 安全修正；
3. 同一控制器 + 动态 CoP/contact-frame 更新；
4. 只有在 FR5 API 允许且实验条件可比时，再比较 explicit force/moment interface。

不能一次同时更改估计器、滤波器、控制器和安全阈值；要通过消融实验才能判断性能来源。

### 模块 F：双向刮拭任务状态机与安全监督

建议最少有以下状态：
`IDLE → APPROACH → CONTACT_CHECK → FORCE_RAMP → FORWARD_SCRAPE → TURN → LIGHT_RETURN → RELEASE`
以及任何状态均可进入的 `SAFE_STOP/SAFE_RETREAT`。

每个状态必须显式给出：
- 轨迹参考与更新方式；
- 目标法向力/允许力范围（需来自安全使用包络）；
- 切向速度、角速度与 jerk 限制；
- 接触置信度要求；
- 超时、异常力矩、CoP 偏载、跟踪误差、接触丢失的切换条件；
- 状态切换的速率/连续性约束。

转向应降速、限制接触框架变化并平滑切换目标力。回程不能简单将位置序列倒放而保留全部前向姿态/法向信息；应重用曲面轨迹，但重新计算当前接触几何，并使用更轻的、经过验证的返回接触设定。

安全监督不应依赖一个可能失真的模型输出作为唯一触发条件。必须保留机器人控制器急停/保护停、独立硬限制、看门狗与命令失效处置。

### 模块 G：数据、基准、评价与复现

该模块横跨所有研发阶段，而非系统最后才做。

**实验顺序**
1. 刚性工装：手眼/TCP/工具几何/坐标变换；
2. F/T 标定工装：多姿态重力、bias、漂移、力臂与 CoP；
3. 不同刚度的软体体模：法向、摩擦、滚动/滑动、接触点移动；
4. 运动环/频响：不同频率、命令模式和控制参数；
5. 完整曲面轨迹：轨迹误差、接触力、转向/回程、安全状态机；
6. 故障注入：深度洞、遮挡、时间戳错位、F/T 异常、超时、接触丢失、估计置信度低；
7. 在伦理审批、风险评估与停止标准齐备后，才讨论有限的人体可行性验证。

**每项实验报告都必须记录**
- 设备/固件/SDK/ROS 版本与全部参数；
- 传感器和命令时间戳；
- ground truth 来源与不确定度；
- 所有基线、消融和重复次数；
- mean/RMSE 之外的峰值、百分位、故障与脱接触率；
- 原始数据、预处理脚本、评价脚本和随机种子（若适用）。

**验收指标类型**
- 标定：位置/姿态残差、重投影/配准残差、跨姿态一致性；
- 轨迹：3D 曲线到参考真值的误差、贴面偏差、弧长速度波动、置信度校准；
- 接触估计：CoP 误差、偏载检出率/误报率、wrench RMSE、漂移；
- 控制：目标力跟踪 RMSE/峰值/相位、脱接触率、settling time、转向冲击；
- 系统：任务成功率、异常退出正确率、故障覆盖、端到端轨迹精度；
- 复现性：在相同硬件与版本中重跑的性能差异。

验收阈值不能在缺少工具尺寸、接触面积、用途和安全包络时凭空指定。应先由误差预算和风险分析确定系统容许误差，再分配给标定、轨迹与控制子模块。

### 模块 H：自适应与 residual/offline RL（后置）

RL 不是第一版完成任务所必需的部分。只有当以下条件全部成立后，才有理由投入：
- 基线在刚性工装与软体体模上稳定；
- 控制周期、延迟、接触状态和失败机制可测；
- 具有带覆盖范围/质量标签的离线数据；
- 明确学习策略的动作接口与约束；
- 策略只能产生低维候选修正，如 `Delta Fd, Delta D, Delta vt`，不能直接绕过安全监督下发任意机器人位姿。

若传统控制已经解决主要问题，RL 可能只增加风险和复现成本。若要将 RL 作为论文贡献，必须与固定参数/自适应控制基线公平比较，并评估分布外失败和动作扰动鲁棒性。

## 2. 推荐的分阶段验收门

| 阶段 | 目标 | 通过条件（原则性定义） | 未通过时禁止进入 |
|---|---|---|---|
| Gate 0 | 任务边界与安全方案 | 使用包络、危险分析、急停和异常退出路径获项目确认 | 任何接触实验 |
| Gate 1 | 坐标/时间/传感器 | 刚性工装上重复标定与 wrench 变换可复现；时序延迟可测 | 依赖力矩的 CoP/法向闭环 |
| Gate 2 | 2D→3D 路径 | 轨迹对参考表面/标线的误差可量化，低置信度能被拒绝 | 自动贴面刮拭 |
| Gate 3 | 接触状态估计 | CoP/偏载估计在已知工具与工装上的误差和失效边界明确 | 依赖该状态的姿态自动修正 |
| Gate 4 | 基础力控 | 在安全体模上建立实测时延下的稳定参数域，转向/接触瞬态可控 | 动态人体曲面任务 |
| Gate 5 | 完整状态机 | 前刮/转向/回程/释放全流程有统一日志、故障注入和安全退出证据 | 人体可行性验证 |
| Gate 6 | 高级算法/论文贡献 | 对照、消融、数据与重复实验支持明确增益 | 任何临床或安全效果宣称 |

## 3. 研究贡献应如何收敛

不要同时把“重建、标线、接触估计、变导纳、RL、安全”全部声明为主要创新。较合理的候选贡献有三种，应由早期实验决定主攻哪一个：

### 候选 A：宽刮板在滑动软接触下的动态 CoP/contact-frame 估计
- 研究问题：已知工具几何 + 腕部 wrench + 局部视觉法向，何时能正确估计等效接触位置与偏载？
- 关键风险：摩擦、组织形变与姿态失配混淆；分布压力不可唯一观测。
- 必需证据：刚性曲面 ground truth、软体体模、正反向滑动、不同曲率与接触点迁移。

### 候选 B：面向真实位置控制接口的延迟感知曲面恒力控制
- 研究问题：测得 motion-loop delay 后，离散/jerk-limited/admittance 与动态接触框架是否能降低相位滞后、峰值力和接触丢失？
- 关键风险：必须先识别 FR5 的真实命令/反馈语义；不能把其他机器人的 6 ms 延迟当作本平台事实。
- 必需证据：同一硬件、相同路径/体模/滤波下的公平控制器比较与频响图。

### 候选 C：带置信度的“人工画线→动态软曲面 3D 路径”
- 研究问题：曲面约束与局部动态重投影能否比直接像素深度反投影/刚性 ICP 显著降低轨迹偏差？
- 关键风险：人体曲面数据、时间变化和深度缺失的真实分布必须采集；不能只用干净的离线数据。
- 必需证据：参考扫描/工装曲面、缺失/遮挡分层、端到端 3D 误差与速度。

推荐先完成 Gate 1–4 的工程基准，再选择对系统影响最大、又能由当前传感器观测的候选作为论文主贡献。最有价值的创新不是最复杂的算法，而是找到现有方法无法覆盖、并且我们能够用数据明确证明和解决的问题。

## 4. 文献与开源资源筛选标准（纠正过去“搜到即推荐”）

对每项候选工作先检查以下五个维度，每项 0–2 分：

1. **任务/物理相似性**：是否同样涉及软表面、滑动接触、工具几何、力矩或动态接触？
2. **证据等级**：正式同行评审、实物机器人实验、体模/仿真，还是纯预印本/概念？
3. **接口匹配度**：需要什么传感器、控制层级、采样频率、坐标和计算资源？我们实际具备吗？
4. **可复现性**：官方代码、数据、参数、硬件说明、实验协议是否可得？
5. **决策影响**：读完是否会改变我们的系统结构、控制器选择、实验或论文假设？

总分低或不会改变当前决策的论文只进入补充参考，不再占用深读名额。新近预印本可以由于时效性进入候选，但必须明确标注未同行评审，且不能单独支撑项目的核心结论。相同 DOI/arXiv ID 的不同版本应合并记录；online-first 日期与最终卷期年份分开写。

**每篇被列为重点的论文必须回答：**
- 该方法解决的是哪个模块的哪个具体失败模式？
- 输入、输出及其坐标/频率/单位是什么？
- 需要哪些我们没有的硬件/接口？
- 它相对当前 baseline 的可量化增益是什么？
- 我们用哪一个最小实验能验证迁移假设？
- 若复现失败，最可能失败在哪里？我们如何在预算内止损？

## 5. 对当前调研工作的自我纠偏

### 已识别的问题

1. **容易被新论文牵着走，缺少固定的端到端需求表。** 每轮能发现有趣方向，但没有始终把文献映射到同一张验收矩阵；纠正方式：先定模块与 Gate，再检索。
2. **跨领域可迁移性有时描述得比证据更强。** 超声、抛光、抓取与刮痧虽有相似性，但传感通道、工具几何、接触面积、组织力学和接口层级不同；纠正方式：每篇强制写“可迁移/不可迁移/验证实验”。
3. **容易重复已知资源。** Hydra、Xu 2024、admittance/passivity 等反复出现，新增价值有时只是重述；纠正方式：按 DOI/arXiv ID 建唯一记录，重复引用只说明它在当前决策中的作用发生了什么变化。
4. **硬件接口核验不足。** ROS 2 控制器有公开实现不代表 FR5/ServoCart 就能连接，更不等于具有同样频响；纠正方式：把官方 SDK 版本、命令语义、反馈率、时间戳、停止接口列为 P0，而非持续扩充控制理论。
5. **坐标与 wrench 变换需要更严格的单元测试。** 位置、向量方向、力矩参考点或表达坐标系任何一个约定不一致，CoP 和姿态修正就可能反向；纠正方式：先做已知力臂的正负号/旋转/平移测试，再接软接触。
6. **公式/元数据呈现检查还不够稳。** 部分报告的公式曾以未渲染 LaTeX 残留形式出现；论文在线发表与卷期年份也容易混淆。纠正方式：上传前检查实际渲染后的 Markdown、链接可达性、DOI、日期和文献类型。
7. **缺少一套可共享的基准数据和消融协议。** 若没有参考真值、统一日志与固定基线，就无法判定改进来自估计器、滤波器、控制器还是参数改变；纠正方式：将实验协议和数据 schema 也纳入正式研究产物。
8. **安全研究放得太靠后。** 力阈值、工具边缘、切向摩擦、停止距离与异常退出应先定义，不应等控制器调好再讨论；纠正方式：Gate 0 前置，任何更高层算法不能绕过独立安全监督。

### 每轮新的强制工作流程

1. 读取项目路线图、当前 README、最近两轮原始报告与既有文献索引；
2. 写明最多三个本轮研究问题，每个问题对应一个模块、当前失败模式和预计决策；
3. 先查官方控制/传感器接口和基线实现，再查对应的正式论文；
4. 按筛选矩阵选 5–10 个真正会影响决策的工作，交叉核验 DOI、作者、年份、载体、代码与实验平台；
5. 给每个候选提出最小可证伪实验，而不只写“可迁移价值”；
6. 最终更新结论：已支持 / 证据不足 / 与本硬件不匹配 / 需要自建实验；
7. 建立独立分支，新增本轮 daily 与 all_round 教学模块，按需更新 README、索引、术语与本路线图；
8. 检查数学符号、链接、来源和文件路径，运行 GitHub 读取回验，再开 PR；除非用户明确要求，不自行合并。

## 6. 参考基线与官方资源

以下资源已核验其官方页面，应作为对应模块的起点，不代表所有资源都可直接运行于 FR5：

1. **Xu et al., 2024 — “Toward automatic robotic massage based on interactive trajectory planning and control.”** *Complex & Intelligent Systems*, 10, 4397–4407. DOI: https://doi.org/10.1007/s40747-024-01384-5. 真实机器人按摩的人工 2D 画线→3D 轨迹、刚性点云注册与混合力/位置控制基线。
2. **Hydra — “Marker-Free RGB-D Hand-Eye Calibration.”** arXiv:2504.20584. https://arxiv.org/abs/2504.20584. 含代码、基准数据与 ROS 2 集成；需要在本项目的相机、机械臂和目标精度下独立验收。
3. **Arefin & Tiryaki, 2026 — “Contact-Aware Impedance Controller for Robot-Assisted Ultrasound Imaging.”** arXiv:2609.34400. https://arxiv.org/abs/2609.34400. 预印本；值得迁移的是动态接触位置与 interaction-frame 更新，不是其超声图像接触检测。
4. **Kutsuzawa & Hayashibe — “Simultaneous estimation of contact position and tool shape with high-dimensional parameters using force measurements and particle filtering.”** *IJRR*, 45(7), online first 2025-09-27 / issue 2026. DOI: https://doi.org/10.1177/02783649251379515. 正式期刊；第一版因工具几何已知应先用低维解析估计。
5. **Piedra, Jeffrey & Khatib, 2026 — “Explicit force-based control strategies for compliant robot-assisted ultrasound imaging.”** *The International Journal of Robotics Research*, online 2026-05-01. DOI: https://doi.org/10.1177/02783649261441635. 正式期刊；用作动态力跟踪参考，需先确认 FR5 控制层级能否公平复现。
6. **Mae & Kikuuwe, 2024 — “An Admittance Controller with a Jerk Limiter for Position-Controlled Robots.”** *Journal of Robotics and Mechatronics*, 36(2), 483–493. DOI: https://doi.org/10.20965/jrm.2024.p0483. 位置控制机器人上的离散导纳与 jerk limiter 基线；论文使用 UR3e，不可直接移植其延迟数值。
7. **Iturrate et al., 2025 — “Surface Following using Direct Adaptive Admittance Control.”** IEEE/SICE SII 2025. DOI: https://doi.org/10.1109/SII59315.2025.10870963. 未知曲面在线法向估计与自适应导纳的对照基线。
8. **ROS 2 Control — Admittance Controller.** https://control.ros.org/master/doc/ros2_controllers/admittance_controller/doc/userdoc.html. 官方软件文档；先核验其控制接口、硬件适配与实际发布版本，再考虑接入。
9. **DynamicSurf, 3DV 2024.** https://github.com/Mirgahney/dynsurf. 非刚性 RGB-D 重建代码，作为离线/慢层对照优先，而非实时安全控制依赖。
10. **ISO 13482:2014 / ISO/TR 23482-2:2019.** https://www.iso.org/standard/53820.html 与 https://www.iso.org/standard/71627.html. 用于检查个人护理机器人相关风险和适用性；是否适用必须基于项目预定用途判断，不能从引用标准推断合规。
