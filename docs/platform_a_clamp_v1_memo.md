# 平台 A：足跟夹挤部分 V1 备忘

更新时间：2026-08-19

## 1. 当前目标

本版本只完成“夹挤”部分，不包含后续撬拨。

目标流程是：

1. 摄像头看到足跟。
2. 识别足跟轮廓和左右夹持点。
3. 机械臂移动到足跟夹持位置。
4. 夹爪保持张开，先到达计划的夹挤起点。
5. 停顿确认。
6. 夹爪低速向内闭合设定的夹挤量。
7. 完成后可松开夹爪，并回到软件设定的初始位置。

夹爪的闭合量是“夹挤位移”，不是“最终夹爪开度”。例如视觉测得足跟宽度为 55 mm，设定夹挤 8 mm，则第二阶段的目标开度应为 47 mm。

## 2. 当前夹挤逻辑

### 第一阶段：到夹挤起点

- 使用视觉和深度数据得到当前足跟宽度 `width_mm`。
- 根据 AG95 标定曲线把目标开度换成控制器原始值。
- 机械臂先移动到足跟位置，再让夹爪从张开状态闭合到这个目标开度。
- 到达目标后停顿确认。
- 不再通过“提前碰到足跟的位置”重新计算夹挤基准。

### 第二阶段：实际夹挤

- 目标开度：`width_mm - clamp_mm`。
- `clamp_mm` 是界面中输入的夹挤位移，单位毫米。
- 夹爪低速闭合到第二阶段目标。
- 控制器反馈显示夹爪受到阻挡时，只作为异常或停止条件，不改变原先规划的路线和基准。

## 3. AG95 开度标定

当前使用实际测量的插值曲线，不是简单假设“原始值等于毫米”：

| 控制器原始值 | 实测开度 |
|---:|---:|
| 1000 | 95 mm |
| 800 | 78 mm |
| 600 | 60 mm |
| 400 | 42 mm |
| 200 | 23 mm |

相关文件：

- `platform_a/ag95_opening.py`
- `platform_a/config/ag95_opening_calibration.json`
- `scripts/set_ag95_opening.py`
- `scripts/platform_a_execute_clamp.py`

不要把控制器原始值直接当成毫米。以后如果重新测量开度，应更新标定 JSON 和插值逻辑。

## 4. 视觉和深度算法

当前视觉流程：

- YOLO 只负责识别足跟区域。
- 足跟区域的长轴用于估计足部前后方向。
- 夹爪左右方向取足部长轴的垂线。
- 夹持点由足跟轮廓两侧确定。
- D435 深度数据与足跟局部平面拟合，用三维点距离计算宽度。
- `state_service/d435_monitor.py` 对多帧结果做稳定和异常点过滤。

重要原则：

- 针线不是夹持点识别的必要输入，只能作为辅助显示。
- 运行时不使用画面中的标定板换算足跟宽度。
- 标定板和足跟不在同一平面，用标定板做现场横向比例会随高度和深度产生错误。
- 标定板只能用于相机事先标定；实际运行不要求旁边放标定板。

主要文件：

- `platform_a/clamp_vision.py`
- `state_service/d435_monitor.py`
- `platform_a/main.py`

当前视觉结果中，宽度来源字段为：

```text
heel_width_source = d435_depth_local_plane
```

## 5. 当前已修正的问题

- 修正了“先搜索碰撞位置，再把碰撞位置当夹挤基准”的错误逻辑。
- 修正为“先到视觉计划宽度，再减去设定夹挤量”。
- 修正了静止画面中夹持点单帧跳动造成的显示跳动。
- 增加了多帧夹持点稳定判断和明显跳点过滤。
- 机械臂回零不再因为当前位置距离较远就直接拒绝，路线安全检查仍需保留。
- 运行时删除了标定板毫米/像素比例修正，避免不同平面造成错误宽度。

## 6. 当前已知限制

截至本备忘录更新时间，实际画面中曾测得约 47.15 mm 的深度宽度结果，还没有稳定验证到目标约 55 mm。因此：

- 目前不能宣称深度测距已经完成 55 mm 校准。
- 这不是硬编码 55 mm 的结果。
- 后续应继续检查 D435 深度对足跟球面边缘的取点、局部平面拟合和相机内参，而不是重新加入固定 55 mm 修正。
- 在没有确认宽度稳定前，不建议直接用真实足模型进行自动夹挤。

## 8. 后续 AI 修改时必须遵守

1. 不要把 55 mm、53.6 mm 等目标值写死成视觉测量结果。
2. 不要把单帧宽度直接作为机械臂运动目标，必须经过多帧稳定确认。
3. 不要用提前碰撞位置替代视觉规划的第一阶段基准。
4. 不要在运行时依赖标定板进行横向比例换算。
5. 任何真实机械臂运动修改，先做语法检查和回放模式测试，再进行低速真实测试。
6. 发现路线或夹爪逻辑异常时，先记录当时的原始开度、换算开度、目标开度和控制器状态，再修改算法。
