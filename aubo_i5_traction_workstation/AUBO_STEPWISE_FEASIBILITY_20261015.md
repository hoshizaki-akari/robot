# AUBO i5 低速分步牵引：断机调研与可行性方案

日期：2026-10-15，Asia/Shanghai。范围：独立 AUBO 牵引工作站，不改 FR5，不操作断开的机械臂。

## 1. 结论与证据等级

建议采用 **AUBOPE V4 普通直线移动 + 单步完成确认 + 最新测力反馈**，不再以 200 Hz TCP2CAN 连续路点作为演示原型的必需条件。暂不升级控制柜，不依赖 ARCS，不安装 Gazebo。

这不是“整套牵引已验证成功”。证据分为：

| 项目 | 证据 | 判定 |
| --- | --- | --- |
| 旧版 SDK 普通笛卡尔移动 | 本机此前 5 cm 真机记录，返回 0、到位事件、随后静止 | 单次运动已有成功记录 |
| 分步所需接口 | 本机真实头文件和共享库，11 个方法地址严格编译/链接，动态依赖检查 | 离线 API/ABI 通过 |
| 不积压命令、完成确认、步长及符号计算 | 12 项纯状态/数学契约测试 | 设计不变量通过；不是生产驱动测试 |
| 连续小步重复执行、停止抢占 | 本次机械臂已断开 | 未验证 |
| 省力拖拽、位置牵引、恒力牵引 | 需要接机后的完整实验 | 未验收，不可声称全部可用 |

此前成功记录位于 `debug/session_aubo_i5_tool_x_5cm_20261015/stage_report.txt`：工具 X+ 指令 0.050 m，实测初始工具坐标位移约 `[0.0501356245, 0.0000045885, 0.0000031149] m`，速度设置 0.005 m/s、加速度 0.02 m/s²。记录只证明该次普通相对直线移动，不代表微小步分辨率、重复性、停止延迟或力控稳定性已经验证。

## 2. 为什么选这条路线

现有驱动在同一个 ROS 执行线程中调用同步 TCP2CAN 发送，并在下一次定时回调发现间隔超过 30 ms 后停流。实测调用曾等待约 100–300 ms。它同时拖延 ROS 位姿发布和停止服务处理。

30 ms 是本项目实现的约束，不是厂商给出的设备不兼容结论。不能把“此连续发送方式失败”推广成“普通运动或分步牵引不可能”。但也不能只把 30 ms 改大：旧速度命令可能排队，时间积分可能放大单步位移，状态还会被阻塞。

厂家旧版 SDK 声明了普通直线移动、相对直线移动、移动状态读取、速度/加速度设置及快速停止等接口。普通移动让控制柜完成一段路径，电脑不必在该段内持续补发插补路点。

参考的新项目通过 RPC/RTDE 和 servoJoint 工作，属于另一套控制接口，不能仅凭机械臂同为 i5 就替换。断开机械臂后仍曾出现 TCP 探测显示端口开放，因此端口探测不能证明真机服务存在；必须通过 SDK 身份、状态响应和真实反馈确认。当前不以该探测判断 ARCS 可用或不可用。

## 3. 运动 API 与互斥模式

首选复用此前成功的 `robotMoveLineToTargetPositionByRelative(coord, delta, false)`，每次只给一个很短的平移量，姿态不变。此前成功记录使用阻塞参数 true；本次未验证 false 的真机行为。两者的接口声明、阻塞参数说明及本机符号均已核对。

备用为 `robotServiceRobotIk(seed, position, orientation, target)` 后调用 `robotServiceLineMove(target, false)`，便于明确记录绝对终点。其 API/ABI 已通过离线检查，但在本设备上的分步执行仍须验收。普通 MoveJ 不是受拉牵引的默认替代方案，因为关节运动不保证末端直线路径。

“非阻塞”只是不等待走到终点，不代表网络调用永不阻塞或毫秒级立即返回。仍把调用放在单独工作线程。

运行普通运动前，关闭原 TCP2CAN 发送器，确保没有第二个程序控制机器人，并确认控制器静止。若本工作站持有透传模式，则检查退出结果后交还普通 API 控制；不得靠反复切换模式夺取未知程序控制权。

启动会话时读取实际 TCP、坐标与速度配置；显式设定本会话的低速、加速度和无额外偏移。任何配置失败则不发运动。不能初始化运动属性后沿用默认大速度；不修改固件、安全 IO、碰撞等级。会话结束恢复本会话改动且已知原值的配置。

## 4. 最小执行架构

```text
网页与牵引任务状态
        ↓ 最新有效意图（只保存一份，不排队）
分步决策器 → 单步 SDK 工作线程 → 控制柜自己执行短直线
        ↑                         ↓
  最新测力 + 位姿 ← 独立遥测连接/回调

停止请求 → 独立停止路径 → 停止反馈确认
```

保留网页、COM4 传感器桥、会话记录和现有 ROS 消息。新增 `stepwise` 执行后端，与 `tcp2can` 后端二选一，不同时运行。

需要独立停止连接，是为了避免普通运动 SDK 请求阻塞时只能在同一线程后面排队停止。厂商 API 存在不等于已经证明多连接停止在本固件上可抢占，必须接机专项验证；失败时不能宣布可交互运行。

完整单步状态：

`READY → SENDING → WAITING_COMPLETION → SETTLING → READY`

停止或异常进入 `STOPPING/FAULT`，不自动重放未确认的相对位移。

具体规则：

1. 仅在无在途命令、反馈新鲜且任务仍有效时取一次最新意图。
2. 从真实当前位置生成目标，不累积等待期间的旧速度，不把整段 SDK 等待时间乘入下一步位移。
3. 一次只允许一个运动在途。发送成功只代表被接受，不代表到位。
4. 到位要求：命令已确认接受、在命令之后收到的新反馈、控制器静止、目标误差与残余速度达标，连续至少三个不同反馈序号满足。静止但未到目标不能算成功。
5. 发送超时可能是“机器人接受了但应答丢失”。此时禁止自动重发相对移动；停止并通过真实状态消除歧义。
6. 到位后等待短暂稳定，读取新的测力样本，再决定下一步。
7. 停止、改模式、退出会话立即使旧命令代次失效；旧 SDK 调用迟到返回也不能启动下一步。
8. 重连后不恢复旧运动，须重新确认当前位置、任务和标定。

100 Hz 可保留用于读力、过滤和显示，但硬件下发按“上一步完成”触发。不存在“电脑每秒算 100 次就必须发送 100 个移动”。最终硬件更新率按实测 ACK、运动、到位与稳定总时间报告，不承诺固定频率。

## 5. 步长、延迟与超时

初次空载验收候选：1 mm 单步、2 mm/s、0.01–0.02 m/s²。这是测试起点，不是已验证参数。

闭环候选：单步最大 0.5 mm，接近目标时 0.05–0.2 mm；但必须先测最小可靠运动量与重复性。若微小步根本无法可靠执行，不能靠放大到位容差假装通过，须提高最小步长并重新评估允许的拉力误差。

速度意图转位移用固定短规划窗口，例如 0.1 s：`Δp = clip_norm(v × 0.1 s, max_step)`。限制三维向量的总长度，不是允许 XYZ 各自走完整步长。到总行程边界时裁剪剩余距离；每一步都从测得位置计算，并检查 IK 分支变化。

力调节采用实测带符号梯度 `K = ΔF / Δs`。初始可使用有界比例步进：`Δs = clamp(α × (F目标 − F实际) / K, ±max_step)`，`0 < α < 1`。K 的符号决定该往哪边走，不能直接继承 FR5 的符号假设。K 未确认、接近零或测量噪声过大时不自动调节。V1 不使用积分累积，防止等待期间饱和。

死区应覆盖测力噪声和最小步引起的力变化。若 `|K| × 最小可靠步长` 已大于用户要求的恒力误差，现有分步精度就达不到该指标；只能降低指标或换控制路径，不能伪称恒力精度通过。

分别处理 ACK 超时、运动完成超时、反馈过期，不能用同一个“30 ms 改成 3 s”替代。完成期限参考位移、速度和加速度的三角/梯形运动时间，再加实测通信裕量；采样时钟与任务期限均用单调时钟。SDK 超时不以重复发运动来恢复。

## 6. 三种模式与原功能覆盖

| 功能 | 分步方案 | 保留/限制 |
| --- | --- | --- |
| 省力拖拽 | 超过测力死区，沿已标定的外力方向走一小步；松手后不再发下一步 | 是慢速力引导移动，不冒称无延迟、连续柔顺拖动 |
| 位置牵引 | 分步接近目标拉力，真实静止且力在容差带内稳定后，锁住当时位置 | 依据原代码语义，不擅改为输入坐标的定位任务；锁定后不追着力波动走 |
| 恒力牵引 | 每步结束重测力，低于目标小步增拉，高于目标小步减拉，带内保持 | 是低带宽恒力原型；精度和扰动恢复时间必须实测 |
| 准备/预张紧 | 相同执行器做有限低速步进，达到条件后停止并测力 | 记录累计实际行程，不无限搜索 |
| 方向标定/锁定 | 复用现有任务流程，输入改为经过本机标定的基坐标系力 | FR5 的固定方向符号不能直接沿用 |
| 横向方向自适应 | 无在途运动时重估；有限横向小步、稳定、再恢复轴向调整 | 不把原高频侧向速度直接积压成轨迹；属于后续单独验收项 |
| 减力/释放 | 重测后逐步回退，达到释放条件后停住 | 不靠固定步数假设已经卸载 |
| 设零/返零 | 保存真实零点；普通直线分段返零，每步确认 | 受拉时先完成减力；零点不是自动安全路径保证 |
| 停止/急停/故障恢复 | 意图失效、停止请求、测量静止确认；恢复不自动继续旧任务 | 停止独立路径与多连接行为必须验证 |
| 页面、参数、历史、CSV 导出 | 保留现有接口，增加分步阶段、命令编号、ACK/完成耗时 | 展示真实状态；不得显示假实时值或假恒力成功 |

原连续速度算法的惯性、积分、预测与制动参数不能未经验证照搬到低频步进闭环。可保留其坐标转换、任务状态与记录；V1 用单步比例/死区决策，停稳后重新计算。位置牵引的 SETTLING 判断应取真实执行器静止，而不是仅取软件计算出的零速度。

## 7. 传感器和坐标标定

COM4 原始力读取已经有成功记录，但当前安装四元数仍为未验证占位值。不能只把 `mounting_verified` 改成 true。

保持末端姿态固定时，无外力去零可抵消该姿态下的静态负载偏置。沿已知工具轴的单轴原型可通过人工预张紧建立传感器轴向投影，再通过有限的增拉/减拉步确认梯度符号；该结果仅适用于该轴与已验证姿态，不能扩展成 XYZ 全方向已标定。

完整三维拖拽与自动横向修正需要传感器到法兰的真实旋转。可用多个已知加载方向，或多个无外力稳定姿态下的重力数据拟合旋转、偏置与有效负载；样本方向必须有足够独立性，并用未参与拟合的方向验证。测量噪声、线缆力、工具变更应记录。姿态改变后，不能沿用未经补偿的旧去零结果。

本期只执行固定姿态平移，不主动加入绕针、视觉定位或姿态跟随。工具与法兰不一致时读取实际 TCP，不沿用此前零 TCP 的假设。传感器型号不要求必须受控制柜原生支持，因为原始采样和闭环决策在电脑侧。

## 8. 接回真机后的有限验收

以下是验收计划，不是已完成的结果。各阶段保存命令、真实反馈、测力和简报，失败即停，不无限运动重试。

1. **只读与身份**：SDK 登录、真实模式、六轴位姿、COM4 时序、无竞争控制程序。不能用端口开放或网页缓存证明在线。
2. **单步执行**：先有限次数 1 mm 正/反向，检查方向、位移与到位；再测试最小可靠步长。无运动、错误方向、提前报完成均不通过。
3. **单命令与取消**：有界连续若干步；网络应答变慢期间不能堆积第二个命令。运动中停止后，验证静止及无迟到旧动作；确认独立停止路径有效。
4. **单轴标定**：在实验模型上测去零、载荷方向及小步的力变化符号；用户确认真实增拉/减拉方向。方向未通过不进入力闭环。
5. **位置牵引**：达到一个已选定的低目标拉力、稳定后锁位；保持期间不追逐力波动。记录到达用时、误差、位移。
6. **恒力牵引**：从相同低载荷开始，连续记录至少 30 s；对可控轻微扰动记录恢复时间、力误差和是否振荡。合格阈值根据实测噪声和最低可靠步长明确写出，不事后移动标准。
7. **拖拽与横向修正**：完成相应坐标标定后验证跟随方向、松手停步、反向与改模式；先单轴再扩展 XYZ，不把单轴验收当作三维通过。
8. **原功能回归**：准备、预张紧、停止、释放、设零返零、故障恢复、参数保存、CSV 导出与页面状态逐项检查。全部完成才宣布三模式适配验收。

如普通短直线重复执行也失败，才继续定位控制柜模式/SDK/配置；如运动通过但测力不收敛，则定位符号、噪声、负载刚度与步长。两类问题不得混为“无法驱动”。
