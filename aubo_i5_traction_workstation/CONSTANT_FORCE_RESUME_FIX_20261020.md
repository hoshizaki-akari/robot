# 恒力松绳保持、重新张紧自动继续（更正上一版语义）

## 与 FR5 对照

原 FR5 manager 在 TRACTION 中将 SENSOR_HOLD / SUSPECT / SETTLING / AMBIGUOUS
作为同一轮任务内的零运动阶段；有效方向重新确认后继续轴向牵引。
上一版“负载释放就结束并要求重新开始”不符合此语义，已撤销。

## 原因与修复

AUBO 当前这条力控没有积分项，不能把所有漂移称为力误差积分累积。
已提供日志的无负载残余力约 0.5–1 N，而原方向有效门槛仅约 0.5 N；
微小残余力被归一化成方向，可能继续更新候选方向和侧向跟随。
历史累计侧向位移本身只是诊断，不是持续运动的积分控制输入。

- 删除 LoadReleaseDetector、自动结束和 CONSTANT_FORCE_LOAD_RELEASED 状态原因。
- 仍张紧时，松手不影响恒力牵引；任务状态保持 TRACTION。
- 原始力进入松绳区时立即零输出；不等滤波后的旧张力衰减。
- 保留最后可信方向；重置方向候选/滤波历史和侧向跟随内部输出。
  松绳期间不使用残余力归一化结果，也不累计侧向修正。
- 目标力、方向标定、会话均保留，不发结束/重新开始请求。
- 原始力重新达到张紧区并持续确认 0.20 s 后，重采有效方向；
  原有方向确认流程随后完成，自动恢复同轮牵引，可重复松绳/拉紧。
- 恢复时只把内部渐变目标从当前实测张力起步，平滑回到原目标；用户目标不变。
- 未自动校零、未修改安装方向标定、未把有负载时的力当零点。
- 无效方向期间关闭方向有效标记，网页显示松绳保持、拉紧自动继续。

## 参数与边界

response_tuning.yaml 中 manager 参数：

- constant_force_slack_hold_enabled: true
- slack_release_force_n: 1.2（实际阈值取 min(此值, 目标力*0.25)）
- slack_resume_force_n: 1.8（实际阈值取 min(此值, 目标力*0.40)）
- slack_recovery_confirm_s: 0.20

这是方向/张力有效性迟滞，不是停止本轮会话或改变目标力。
与 FR5 一致的是保持/继续语义，AUBO 的残余力范围仍需自己的有效性参数。
仅凭力传感器不能无歧义区分所有微小负载和零漂；实际阈值可能需要后续数据校验。
拖拽速度曲线、松手制动及位置牵引不在本轮改变。

## 验证

编译、核心策略与方向模块测试通过。
manager ROS 测试覆盖：持续张紧、任意轴低力噪声不转向、松绳保持零侧向输出、
原方向自动恢复、新方向自动恢复、两次恢复仍为一个会话、用户停止仍能结束。
运行环境参数回读后再交付；未自动试动真实机械臂。

人工检查点：保持同一个目标力；松手仍张紧时继续牵引；松绳时停稳不乱转；
再次拉紧后不点开始也自动恢复，导出完整 ZIP。
