# 牵引信号链路复核与恢复修复（2026-10-21）

## 原始证据

- session_1792565655513：位置牵引由 19 N 切换至 12 N 后，FollowModeJointMove 返回 10023，随后进入故障。
- session_1792565783916：恒力牵引 12 N 时，同一调用返回 10023，随后进入故障。
- 本机使用旧版 V4 SDK；其 10023 是 ResponseReturnError（服务端返回错误），并非碰撞专用错误。原日志没有控制器事件回调，不能追溯确定服务端拒绝的具体原因。
- 两次记录中的诊断、关节与位姿反馈仍然更新。此前代码将运动应答异常直接锁存故障；复位又强依赖 FastStop 应答，导致设备已静止但仍提示“停稳尚未确认”。

## 修复后的链路

1. 正常零速、换向和目标附近保持继续使用跟随模式，不再反复 FastStop/重新跟随。保持目标使用发送时最新实测关节位置，而非队列中的旧种子。
2. 只有跟随模式下、真实反馈健康且新鲜的 10007/10023/21005 才进入可恢复暂停。先停止并确认停稳，再接收当前新目标；不重发失败请求，不恢复旧终点。
3. 人工停止立即取消自动继续。真实关节越界等控制器错误事件仍锁存故障。新增控制器事件回调与粘性错误记录，避免错误被后续普通事件覆盖。
4. FastStop 应答超时不再等同于物理停不下来：仅当请求完成后出现三帧新关节反馈，诊断与 RobotStopped 状态也在请求之后更新、状态健康且关节/笛卡尔速度均静止时，才接受物理停稳证据。调度层还继续要求成功结果之后的新停稳帧。显式硬错误不能按此路径忽略。
5. 停止超时预算独立设为 5 秒；普通运动应答预算不因此扩大。查询与发送共用 SDK 会话时为诊断/状态查询保留调度机会，降低高频发送导致反馈饥饿的可能。
6. 增加通信恢复次数、实际速度、停止预算、跟随保持方式和控制器事件诊断字段。

连续异常最多允许 10 秒窗口内三次确认停止后的恢复；持续拒绝、反馈失联或不能确认停稳时仍停止并报告原因。不能通过无限忽略通信错误来保证闭环，也不能保证今后只有碰撞或限位才会停止。

## 使用

启动：在本项目目录执行 `bash start_workstation.sh`。刷新网页后，设备就绪时重新初始校准并开始所需模式。

出现真实故障时使用网页“故障复位”，成功后重新校准并手动开始，不会自动接续故障前运动。若复位失败，保留具体诊断与完整导出日志，不需靠反复重启掩盖状态。
