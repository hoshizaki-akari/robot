# 位置目标收敛与保持超时修复

记录：session_1792562522722；目标 18 N，最高 17.4936 N，最终 ROS2_CONTROL_ERROR。
第一故障为 hold brake SDK result 10007，调用耗时 0.999143 秒。
厂商本地头文件将 10007 定义为 ErrCode_RequestTimeout。

## 修改

位置牵引原先从力误差中扣除 1 N 完成容差，导致在 17 N 附近停止调节。
新增 stepwise_position_regulation_deadband_n（默认 0.15 N），与完成容差独立。
位置调节在精度区间外使用完整误差计算平滑速度，进入精度区间后才停止。
这避免控制量在精度区间边缘渐近到零而始终无法进入完成确认。
设定 18 N 的实际目标区间为 17.85–18.15 N；测量噪声和机械响应仍影响实际结果。
恒力牵引现有死区和平滑公式保留。

正常保持的制动请求遇到 RequestTimeout 时，只补发一次同类制动；
仅在 epoch 仍有效、任务未取消时补发。重新收到成功应答才返回成功，
两次失败仍返回故障。运动请求不重发，超时不被当成停止成功。
显式停止和取消流程继续由原有停止线程处理。

- 两个 ROS 包编译通过，基础检查 61 项通过。

- SDK 离线回归覆盖保持超时后成功、再次超时、其他错误；检查未重发旧运动。
- 驱动 9 个 CTest 套件通过；牵引模块 17 个套件结果见本次 stage_report.txt。
