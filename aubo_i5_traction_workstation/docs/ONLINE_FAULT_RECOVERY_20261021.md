# 三种牵引在线故障恢复与完整复核

## 原因与修复范围

session_1792564434495 的首故障是 FollowModeJointMove 返回 10007，请求结果不确定。
后续停止已确认，但驱动调度器锁存 FAULT；上层复位要求驱动健康，形成恢复断路。
本改动补齐软件故障的在线恢复，不把超时运动重新发送，也不自动继续旧任务。

## 使用方法

网页出现“故障”后，原“初始校准”按钮显示为“故障复位”。点击一次，等待结果。
成功后按钮恢复为“初始校准”。松弛牵引带，重新初始校准；位置/恒力模式再确认方向、
设置目标并手动开始。省力拖拽则初始校准后手动开始。无需关闭网页或重启程序。
若连接、诊断或停止未确认，网页会说明失败原因；解决实际问题后可重试。
实体急停继续使用控制柜/示教器恢复流程，软件故障复位不解锁实体急停。

## 实现与复核

- 新增驱动 ROS 服务 /aubo_v4_state_node/recover_fault。
- 驱动检查实时健康、实测静止、停止应答后的三份新反馈、旧发送/停止任务及结果队列
  已排空，才清除软件故障。未确认停止时，单次恢复操作可请求一次停止，限定等待时间。
- 成功后驱动为 DISABLED，递增 epoch、丢弃旧速度/端点/模式意图；必须重新激活并收到
  新速度才能运动。不会上电、松闸、清除控制柜报警或重发未知结果的运动。
- Web 桥先复位驱动，再等待健康传播并复位管理器。复位操作串行；普通启动/目标/模式
  更新在复位期间被拒绝，停止与急停仍可发出。急停状态不会被复位请求绕过。
- 管理器清除旧方向、旧目标已配置标志和会话状态，发布 DISABLED，回到 READY。
- 更新网页按钮、重复点击处理和脚本缓存版本；避免浏览器沿用旧恢复入口。
- 同步关闭管理器“初始校准”或普通 reset_fault 绕过 EMERGENCY_STOP 的旁路。

## 验证

- fr_traction、aubo_v4_driver 编译通过。
- 基础 Python 检查 66 项通过。
- 牵引 CTest 共 17 套件通过，管理器 23 项 ROS 用例通过。
- 驱动 CTest 共 9 套件通过，包含 SDK 构造拦截的离线真实节点测试。
- 新回归覆盖三种模式完整恢复及再次启动、过期/移动反馈拒绝复位、停止应答失败拒绝、
  旧请求与结果未排空拒绝、旧 epoch 应答不能恢复运动、复位后无速度重放、断连拒绝、
  重复恢复、等待有界、健康传播延迟、恢复失败不调用上层复位、急停不旁路。
- 浏览器在原真实故障状态下验证“故障复位”按钮显示；部署后验证真实连接与静止状态。

通信失败或自动重放运动。下一次真实软件故障时，需人工点击复位并导出结果完成现场验收。
