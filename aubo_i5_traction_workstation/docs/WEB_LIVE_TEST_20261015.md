## 后续定位与当前状态（20:57）

仅修改独立 AUBO 项目，未修改原 FR5 项目。用户确认示教器没有运行程序。
数字输出通知不能作为存在其他运行程序或故障的证据。

驱动改为两个厂商连接：运动控制与遥测分开，使用厂商路点推送回调；
诊断查询在独立线程运行。读取超时仅在连续三次前有限重试；该重试不会
复位任何运动故障。发生运动故障后仍继续发布真实位姿，避免网页冻结。
增加缓冲状态、请求计数和厂商事件计数。IO 通知与其他事件分别记录。

针对本进程两个控制柜连接启用 TCP_NODELAY，并在 SDK 请求期间刷新
TCP_QUICKACK。抓包确认主机延迟 ACK 已改善，但没有解决连续运动应答阻塞。

捕获的一次 TCP2CAN 调用：请求发送约 76 微秒，SDK 随后等待应答约
312 ms；期间主机对控制器消息的 ACK 很快。其他零速度测试测得
单次发送约 91–136 ms，超过保留的 30 ms 时间间隔限制，自动停流。
这说明 ROS 状态查询阻塞不是唯一原因；尚不能仅凭这些数据断言是固件故障。
数组接口中的 FK 是本地运算，换成 vector 接口仍未解决。
未通过测试的 100 ms 相同位姿预填方案已经撤掉。
零速度测试失败不等价于已经验证所有非零轨迹必然失败。
