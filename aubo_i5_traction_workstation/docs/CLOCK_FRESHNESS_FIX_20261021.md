# 闭环时间戳误报修复（2026-10-21）

## 证据与范围

最新本地会话 `session_1792561588790` 在位置牵引接近 25 N 目标时
报告 WRENCH_INVALID。故障日志中单调接收年龄仅 0.011 秒，位姿年龄
0.034 秒，但力源时间戳年龄为 1.473170 秒。运行记录墙钟跳过约 1.47 秒，
waypoint 序号仅从 9278 到 9281，最大控制周期间隔仍为 0.011082 秒。
这与墙钟跳变造成源时间戳误判一致；尚不能据此确认具体的 Windows/WSL 校时来源。
这不是上一轮 SDK 10007 请求竞争问题，也不表示所有硬件故障均为误报。

## 修改

- 管理器、控制器、力变换层拒绝过期、未来、重复和乱序源时间戳，
  不再用这种帧覆盖上一份有效数据，也不刷新其单调接收时间。
- 墙钟前后跳变时重建时间戳排序基准，使恢复后的新数据可以被接受。
- 真实持续缺少有效数据仍按原有接收超时停止；不永久沿用旧力值。
- 管理器校准、释放、回零等待、到位确认、控制周期、激活确认及会话经过时间
  改用单调时钟。历史记录的日期和消息头仍使用 ROS 时间。
- 去除同一回调内重复读取墙钟进行第二次有效性判定的竞争窗口。
- 不修改 FR5 项目，不调整力/速度/位移参数，不自动启动运动。

## 验证

- fr_traction 编译通过，基础 Python/静态检查 61 项通过。
- 17 个 CTest 套件均已通过（管理器套件修正预期故障分类后单独重跑通过）。
  新语义下持续坏时间戳导致 WRENCH_TIMEOUT，而非立即 WRENCH_INVALID。
- 力变换 21 项、管理器 ROS 集成 18 项通过；包含短暂时间戳异常恢复、
  持续过期超时、墙钟前跳/后跳、重复帧不能延长有效期等回归。
- 新版启动日志：`debug/session_20261021_135952_workstation`，启动到 READY，
  未自动开始牵引。静止观察见 `debug/session_20261021_clock_fix/`。
