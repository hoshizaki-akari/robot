# 省力拖拽阻抗与松手晃动复核

## 结论与适用范围

只优化 AUBO 副本的 XYZ 省力拖拽。未修改 FR5 工程、位置牵引或恒力牵引控制策略，也未提高最高速度、力或位移上限。本轮自动验证只覆盖软件与空闲连接，不代表真机手感已经达标。

“阻抗大”不等于最高速度低：它包含起步/换向延迟、持续推动时的阻尼，以及偏离旧目标后被拉回的弹簧感。应先消除错误方向和多余位置记忆，不能只不断放大力增益。

## 实现修复

1. **消除换向横向弹簧记忆**：原跟随参考在小于 60° 的换向中会保留旧目标相对实测位置的整段误差。即使整体前向，其某个分量也可能反向。拖拽现在只保留沿当前输入方向的前向提前量，丢弃旧横向分量；X/Y/Z 的目标增量与当前输入共线。其他牵引模式保持原策略。
2. **松手减速保持**：仅拖拽松手时，根据最新关节位置和短时滤波速度，生成一个向运动前方的有限减速终点，而不是追赶已经落在身后的采样位置。预测时间最多 40 ms，距离同时受 v²/(2a)、既有关节连续性边界及其 20% 子边界约束；不积累、不重复积分。反馈已静止或不新鲜时不做速度外推。
3. **终点关闭提前到达**：拖拽保持调用 SetNoArrivalAhead，避免运动中的提前到达/混合规则继续影响最终停稳。再启动时重新安装运动跟随设置。仍使用 FollowModeJointMove，不在每次换向反复 FastStop。
4. **抑制松手后重新触发**：启动施力门槛仍为 0.65 N，松手门槛仍为 0.35 N；重新启动要求持续约 30 ms，避免短促振动尖峰反复启停。低于松手门槛仍立即输出零，不增加松手确认等待。
5. **减轻起步黏滞**：仅拖拽的指令加速度由 0.6 调至 1.2 m/s²，不改线性力增益及最高速度。此为主机指令响应设置，不代表实际机械臂能达到同样加速度。

## FR5 与本机原生能力

- 实际 FR5 源码 fr5_direct_driver_node.py 使用 EndForceDragControl，在机械臂控制器内持续运行拖拽；不是简单地由电脑按同一频率发送位置点。
- 本机使用的确实是官方 AUBOPE V4 SDK，当前路径是 FollowModeJointMove。不能把现代 ARCS 的 servoJoint、ForceControl API 当作这台 V4 固件已有功能。
- 本机 serviceinterface.h 存在 rootServiceRobotControl，枚举有 EnableForceControl/DisableForceControl，诊断有 forceControlMode；也有 TCP2CAN 透传入口。接口存在不代表已经验证支持本工作站的外置 KWR75D、固定姿态 XYZ 助力和当前参数。
- TeachStart 是指定轴/方向的点动，不等于力引导拖拽。TCP2CAN 也不是自动力控，仍需主机闭环、周期管理和实机兼容验证；此前失败记录不能被“接口声明存在”覆盖。
- 本轮未自动进入未知原生力控，也未切换透传模式。若本轮仍不能达到所需手感，下一步应单独验收控制器原生拖动或经验证的周期伺服链路，而不是继续把当前路径的增益放大并承诺等同 FR5。

官方旧版接口参考：https://github.com/AuboRobot/aubo_robot/blob/master/aubo_driver/include/aubo_driver/serviceinterface.h

以上公开头文件与本机安装版本并非逐行相同；FollowModeJointMove 的具体可用性以本机安装头文件和既有成功运行记录为依据。
