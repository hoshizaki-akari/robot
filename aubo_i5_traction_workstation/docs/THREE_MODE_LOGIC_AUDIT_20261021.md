# 三种牵引模式：超时、恢复及误停审查

日期：2026-10-21；范围仅 AUBO i5 牵引工作站。

## 本轮日志事实

`session_1792560819058_full_log.zip` 是位置牵引（operation_mode=1），运行中目标从 10 N 调到 24 N。

停止证据：

- 运动接口返回 `FollowModeJointMove SDK result 10007`。
- 同时读状态返回 `robot state query failed: 10007`。
- 最后逆解成功，最大关节变化约 0.007075 rad；不是上一轮的逆解步长错误。
- 位姿推送仍有新数据，随后状态查询恢复成功；不能把此事简单等同于网线断开。
- SDK 头文件 `AuboRobotMetaType.h` 将 10007 定义为 `ErrCode_RequestTimeout`。官方 [V4 用户手册](https://www.aubo-cobot.com/public/assets/aubo/downloadsen/UM/AUBO-i5%20%26%20CB4%20user%20manual/AUBO-i5%20%26%20CB4%20user%20manual_V4.5.11_2021.05.19.pdf) 同样列出该定义。

SDK 二进制内部、控制柜负载和网络层并未全部被观测，不能断言全部超时一定由并发造成。代码中普通运动 RPC 与读状态 RPC 确实可以并发；本轮先消除这一可控冲突，并准确区分读失败与运动执行不确定。

## 修复

1. **普通 SDK 请求互斥**：IK、运动参数、跟随发送与同步查询不再交叠；实时位姿回调不经过该锁，紧急停止专用通道保留。正常查询在运动请求排队时让行。
2. **读超时不伪造新状态**：只有 10007 可以保留上一份成功样本及其原始时间戳。驱动仍执行现有 1.2 s 状态／诊断有效期及 0.5 s 位姿有效期检查；持续失联照常停止。查询超时期间 `stopped=false`，不能利用旧“停止”状态确认到位或恢复。明确的控制柜报警、断连和无效数据立即使健康检查失败。
3. **停止结果原子交接**：结果入队与 `stop_in_progress` 释放在同一把锁内完成，防止上层已经消费停止确认、下一条命令却仍被底层旧停止标记拒绝。
4. **近目标微调误停**：无进展判断同时要求经过两秒及累计请求净位移达到两倍到位分辨率。小力误差产生的微小速度，不再仅因两秒内不到可辨位移而被判堵转。零速／恢复会清理旧累计量；反向请求抵消旧净位移。真正持续请求运动但不移动仍有故障判断。
5. **保留具体故障原因**：失败 ACK 将实际 SDK 返回信息传给调度器，避免只剩笼统 `command acknowledgement failed`。新增读超时计数和请求串行化诊断字段。

没有扩大力、速度或行程阈值；没有自动重发返回超时的运动命令。运动超时可能是已执行但确认丢失，仍会停止并保留返回码，不能将其冒充成功。

## 三种功能审查与回归

| 范围 | 核对与验证 |
| --- | --- |
| 省力拖拽 | X/Y/Z 及旋转工具坐标变换、正反向切换、力量到速度映射、松手零输出、残余力不重新触发、制动不发送旧关节目标 |
| 位置牵引 | 独立接近／微调逻辑、到位确认、保持、修改目标恢复、开始／停止及重复会话；微小命令不继承固定两秒误停 |
| 恒力牵引 | 正负力误差、近目标连续输出；松绳仅暂停，不完成会话；重新拉紧后自动恢复同一会话，方向变化重新确认 |
| 跨模式 | 活动状态不允许混切模式；停止取消延迟启动；旧 epoch 的 ACK 不得恢复运动或覆盖新故障；底层停止完成后才能重新发命令 |
| 通信及数据 | 单个读超时保留旧时间，不能虚报静止；明确失败使健康无效；运动超时不重发；SDK 调用与只读查询互斥 |

本轮直接修改共享驱动和调度器；控制器／管理器现有语义未改写，使用现有 ROS 集成测试检查三种模式及切换路径。
