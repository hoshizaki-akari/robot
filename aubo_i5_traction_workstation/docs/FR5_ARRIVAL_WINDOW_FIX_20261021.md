# 恢复 FR5 到位范围，修正到位与停稳顺序

## 日志证据

session_1792563208727 的目标为 10 N，后段真实反馈约 9.6–10.3 N。
停止的第一故障为 diagnosis stale，随后 ROS2_CONTROL_ERROR；
诊断年龄到达 1.204348 秒，不能把此真实缺少新诊断的状态直接当成到位。
但在此之前，位置任务本应已完成到位判定，停止持续精调。

原版 FR5 和本地 AUBO 任务配置均为 position_reached_tolerance_n=1.0、
position_reached_confirm_s=1.0。AUBO 控制器上一轮新增的 0.15 N 精调区间
通过 SETTLING 阶段间接收紧了任务到位门槛，且管理器要求先静止再请求停止。
两者导致任务已进入原版范围却仍不断调节，迟迟不进入 POSITION_HOLD。

## 修改

- 到位范围保持原版目标 ±1 N，连续确认 1 秒。
- 精调继续朝目标中心收敛，但 0.15 N 精调阶段不再阻塞任务到位确认。
- 范围确认后立即发布 DISABLED 并请求控制器停止；等待实测静止后才报告已到位。
- 停止等待期间不发送调节运动；正常停止等待最多沿用现有 5 秒确认窗口。
- 停稳时再次核对当前目标。等待期间改变目标或力已离开范围，则恢复当前目标调节，
  不错误确认旧目标完成。手动停止、复位和故障会清除待到位标志。
- 保留真实数据断流和设备错误检测，不将诊断超时伪装为成功。

## 验证

新增 ROS 管理器集成回归，直接复现 10 N 目标、9.6/10.4 N 实际力、
未进入精调 SETTLING 且运动未停的情形。验证不足 1 秒的到位不算完成，
持续到位先发停止，再等待静止确认，并覆盖停稳期间改目标和到位后改目标。
同时修正测试工具的满容量 deque 游标，避免测试等待不到后来收到的静止反馈。

完整测试结果、启动状态和人工验收项见 debug/session_20261021_arrival_fix/stage_report.txt。
本修改仅属于 AUBO 独立工作区，FR5 源码未改动。
