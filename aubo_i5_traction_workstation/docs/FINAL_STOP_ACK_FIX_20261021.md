# 停止最终确认修复

## 会话证据

session_1792563744340 先完成了 10 N 到位（TRACTION -> POSITION_HOLD），
然后修改目标到 24 N 并继续牵引；真实力最高达到 24.8415 N。
在到位停止过程中，驱动记录 stop SDK results 10007,0，却将其判为
stop acknowledgement failed，导致 ROS2_CONTROL_ERROR。
诊断、状态和力数据当时仍新鲜；本轮第一故障不是数据时间戳或到位范围。

## 修改

停止线程先发即时制动，再等旧发送任务结束，最后通过发送会话发送最终停止。
如果第一次仅为 RequestTimeout，不能确定它是否执行；在旧发送结束后，
最终停止返回 0 已明确确认此后的停止请求。此前将两个返回值做严格 AND，
使已成功的最终停止仍被第一轮超时覆盖。

现在仅对“第一次成功或请求超时，最终停止成功”的组合接受最终应答。
最终失败、两次超时、第一次明确错误仍失败；旧发送未结束时不确认停止。
应答成功仍须通过原调度器的实测静止判定，不等于已经物理停稳。

另外对发送已静止时的单次停止路径补齐相同超时恢复：仅重试一次制动，
收到成功应答才确认；不重发运动指令。

## 验证

驱动编译通过，9 个 CTest 套件通过。新增回归包含：
10007/0 成功，0/10007 失败，10007/10007 失败，10001/0 失败，0/0 成功；
检查最终停止必须晚于旧发送结束，以及旧 epoch 的运动不能再提交。
单停止路径覆盖超时后成功和持续超时失败。
真实功能验收仍需网页手动测试；不会自动重放这次运动。
