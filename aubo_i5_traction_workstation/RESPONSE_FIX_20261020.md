# 拖拽换向、响应与两种牵引连续跟随修复

本次输入是 2026-10-20 的三个完整日志：
`session_1792479351852`（拖拽）、`session_1792479627547`（位置牵引）、
`session_1792479752000`（恒力牵引）。

## 日志中实际发生的事

- 拖拽：命令速度中位值 50 mm/s，实测速度中位值约 6.7 mm/s；
  原跟随端点每 100 ms 更新，前看 150 ms，关节速度／加速度还卡在
  0.2 rad/s 和 0.5 rad/s²。施力过零触发 FastStop 和停稳重启。
- 位置牵引：命令速度中位值 1.2 mm/s，约 1.22 s 才确认下一步；
  使用普通 LineMove，而不是拖拽中已经使用的原生 FollowModeJointMove。
- 恒力牵引：同样被默认 0.0002 m/s/N 增益和走停调度压慢。最终停止是
  SDK diagnosis 时间超过旧的 0.5 s 共享门槛；停止前 SDK 返回码仍为 0，
  不能将其描述成超力或机器人故障码。

日志中的极端瞬时速度尖峰来自接收时刻差分，不拿它当作机械臂可达速度证明。

## 修改

1. 拖拽输入明显换向时重置旧方向滤波尾迹；松手过零立即输出零意图。
2. 完整工作站启用原生跟随的实测位置 hold：过零时更新到当前实测位置，
   不进入 FastStop／停稳／重新启用的整套流程；明确停止、过期输入和故障
   仍走原有停止路径。hold 只有在实际停稳反馈确认后才能报告 idle。
3. 跟随端点计划更新间隔改为 30 ms，前看改为 80 ms；实际发送仍受 SDK
   返回时延和新实测位姿到达速度影响，不宣称硬件已经达到 33 Hz。
4. 位置／恒力／释放也使用原生跟随，不再每个小端点等待完成后才发下一步。
   小于旧到位容差的连续微调不再被直接丢弃。
5. 拖拽低力段输入增益设置为原来的 4 倍，关节跟随速度和加速度档也为
   原来的 4 倍。保留既有 50 mm/s 拖拽饱和速度，因此饱和区不是再乘四。
6. 跟随路径不再反复设置与关节跟随无关的直线速度配置；变化不足 5% 的
   已验证关节配置复用读回结果，减少同步 SDK 配置调用。
7. 两种力牵引的增益为 0.004 m/s/N，连续调节下限 0.5 mm/s，最大仍为
   20 mm/s；这替换了长期落在 1.2 mm/s 的默认 fallback。
8. diagnosis 查询完成就发布，不再等后续 state 查询一起返回。
   diagnosis/state 采用独立的 1.2 s 新鲜度预算；位姿仍独立检查，
   SDK 实际返回失败或报警仍立即呈现。
