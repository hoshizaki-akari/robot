# 松手保持、噪声起动与跟随时序修复

## 证据

输入三个完整日志：`session_1792482660908`（拖拽）、`session_1792482829004`
（位置牵引）、`session_1792482876956`（恒力牵引）。
拖拽约 2506 条力向量模长低于 0.5 N 的记录中，有 1063 条仍输出非零运动指令。
原参数死区 0.15 N、最低速度 5 mm/s、有效力增益 0.32 m/s/N，残余力容易触发运动。
末次错误是停止流程返回 `stop SDK results 0,10007`，不能归因于通信断线。
应答计数增量反映的活动吞吐中位数约 20 Hz；10 Hz 快照不能测量精确逐包间隔。

## 本轮实现

- AUBO 专用原始力迟滞门：0.65 N 起动，低于或等于 0.35 N 立即释放；
  释放后小于 0.65 N 的残余力不重新起动。释放直接清空滤波历史。
- 拖拽取消最低速度跳变；有效增益改为 0.032 m/s/N，仍在约 5 N 达到
  150 mm/s 指令上限，避免亚牛顿残余力就使速度饱和。三轴和换向均保留。
- 保持指令直接传实测关节角，不做新的笛卡尔逆解，也不追赶旧运动目标。
- 发送线程已空闲且意图撤销时只调用一次停止；有在途发送时仍先停止、等待发送
  退出、再停止。任何实际失败仍报错，不把 10007 当成功；物理停稳仍由反馈确认。
- 保留停止失败详情，修复空的 fault_reason。
- 增加 `ik_duration_s`、`motion_call_duration_s`、`dispatch_interval_s` 及各自最大值。
  保持/停止后重新建立计时基准，避免把松手等待误算作持续发送间隔。

## 验证与边界

编译、核心/调度/SDK替身测试、生产参数 ROS 集成测试通过，Python 检查 61 项通过。

空闲单次停止、停止失败保留、有在途指令时的停止顺序。
工作台已在无主动牵引的状态启动 READY；实际参数已读取核对。
